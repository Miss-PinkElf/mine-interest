## 目标与成功标准

1. 新增 `tools/prod_env/prod.sh`，支持 `start` / `stop` / `status` 子命令。
2. `prod.sh start` 后：
   - 生产容器 `napcat` 处于 `running`；
   - 生产 AstrBot（`~/.astrbot`）在 `6185` 提供 Dashboard，并在 `6199` 监听反向 WS；
   - `wait_onebot.py` 连生产 OneBot（`13001`）调用 `get_login_info`，返回 17号 `3254276668`；

   - 打印 Dashboard、NapCat WebUI、OneBot WS 三个入口。
3. `prod.sh stop` 后：生产 AstrBot 停止、`napcat` 容器停止；不触碰 E2E 容器与测试 AstrBot。
4. `prod.sh status` 能一眼看出生产 NapCat、生产 AstrBot、E2E 机器人、`production-stopped` 标记的状态。
5. 不把 token、密码写入仓库；运行时从本地配置读取。

## 方案设计

### 文件与常量

**新增文件**

- `tools/prod_env/prod.sh`：唯一入口。
- `tools/prod_env/README.md`：用法、拓扑、与 E2E 的边界、FAQ，带中文 `Metadata（元数据）`。

**运行时读取，不硬编码敏感值**

- 生产编排目录：`${HOME}/napcat`（可用 `PROD_COMPOSE_DIR` 覆盖）。
- 生产容器名：`napcat`（`PROD_CONTAINER`）。
- 生产 AstrBot 根：`${HOME}/.astrbot`（`PROD_ASTRBOT_ROOT`）。
- 生产 QQ：`${PROD_QQ:-3254276668}`；配置路径 `~/napcat/config/onebot11_${PROD_QQ}.json`。
- OneBot 容器端口与 token：用 `python3` 从 `onebot11_${PROD_QQ}.json` 的 `websocketServers[0]` 读取；宿主端口用 `docker port napcat <container_port>/tcp` 解析，失败再回退 `13001`。
- AstrBot Dashboard 端口：默认 `6185`，可用 `PROD_ASTRBOT_PORT` 覆盖。
- AstrBot PID 文件：`${HOME}/.astrbot/.prod-run.pid`（由前台标签内的 shell 写入，`exec` 后 PID 即 AstrBot 进程）。
- iTerm 窗口 ID 文件：`${HOME}/.astrbot/.prod-iterm-window-id`（只存内部窗口 ID，不涉及可见标签名）。
- AstrBot 运行日志：直接看前台标签；不再单独重定向日志文件。
- `wait_onebot.py`：复用 `tools/napcat_e2e/wait_onebot.py`，通过相对路径调用，不复制。

### `prod.sh start`

1. 参数解析与预检：
   - `--no-wait`：只启动，不做 OneBot 就绪校验。
   - `--restart`：显式重启；先停生产 AstrBot，再重启 `napcat` 容器，然后重新拉起 AstrBot 标签。
   - `--no-iterm`：不打开 iTerm2；NapCat 就绪后在当前终端前台运行 AstrBot（Ctrl-C 或关闭终端即停止）。
   - `--help`。
   - 检查 `docker info`、`~/napcat/compose.yaml`、`~/.astrbot`、`astrbot` 命令。
2. 幂等判断（未加 `--restart`）：
   - 若 `napcat` 容器运行中**且** `6185` 已在监听：视为完全就绪，打印「已在运行」和入口后退出 0；
     不启动第二个 AstrBot、不重复开标签、不重启容器。
   - 只有部分在运行（例如容器在跑但 AstrBot 没起）：继续补齐缺失部分，不重启已在运行的部分。
3. `--restart` 重启动作：
   - 停止生产 AstrBot：
     - PID 文件对应进程存活：发 `SIGTERM`，最多等 10 秒；AstrBot 前台标签随之关闭。
     - `6185` 在监听但没有有效 PID 文件：说明是桌面 App 或其他方式启动，**拒绝重启并退出**，不杀未知进程。
   - 重启 NapCat：`cd ~/napcat && docker compose restart napcat`；容器不存在则 `up -d`。
   - NapCat 日志标签里的 `docker logs -f` 会跟随同一容器继续输出，不需要重建。
4. 17号 冲突处理：
   - 若 `napcat-e2e-bot` 正在运行：打印警告并 `docker stop napcat-e2e-bot`（已确认自动停）。
   - 若原生 QQ 正在运行：仅警告，不阻断（Docker 登录会把同账号原生端顶下线）。
5. 启动生产 NapCat：
   - `cd ~/napcat && docker compose up -d`（幂等，使用现有容器与数据卷；`--restart` 已重启过则此步为 no-op）。
6. 启动生产 AstrBot：
   - 若 `6185` 已在监听：视为已运行，跳过启动并提示。
   - 默认开 iTerm2：
     - 读取 `${HOME}/.astrbot/.prod-iterm-window-id`，校验该窗口是否仍存在；
     - **窗口存在**：在该窗口新建一个 AstrBot 标签（NapCat 日志标签视为已存在）；
     - **窗口不存在或没有记录**：新建一个窗口，同时创建两个标签（NapCat 日志 + AstrBot），并记录新窗口 ID；
     - 不设置任何可见标签名。
     - 标签 1（NapCat）：`docker logs -f napcat`；
     - 标签 2（AstrBot）：`cd ~/.astrbot && echo $$ > .prod-run.pid && exec astrbot run`。
   - **AstrBot 在前台标签运行，关闭标签即停止 AstrBot**；日志直接显示在标签里。
   - `--no-iterm`：先完成第 7 步 OneBot 就绪校验并打印入口，再在当前终端执行
     `cd ~/.astrbot && echo $$ > .prod-run.pid && exec astrbot run`；脚本此后被前台进程接管。
   - iTerm.app 不存在或 AppleScript 执行失败：打印手动命令并以非 0 退出；不自动改为 detached，避免产生无法管理、关终端也不停的进程。NapCat 容器可保持运行。
7. 就绪校验（除非 `--no-wait`）：
   - 默认 iTerm 模式：先等 `6185` 监听（最多 120 秒），再等 OneBot 就绪；
   - `--no-iterm` 模式：AstrBot 尚未启动，只等 OneBot 就绪；
   - 解析宿主 OneBot 端口与 token，循环调用 `wait_onebot.py <port> <token> 3254276668`，最多 600 秒；
   - 超时则提示打开 `http://127.0.0.1:16099/webui` 检查是否需要重新扫码，脚本以非 0 退出，但不停止已启动的 NapCat 容器。
8. 清理过期标记：
   - 成功启动生产容器且 E2E 机器人未运行时，删除 `~/.qq-e2e-docker/production-stopped`，避免 `stop-all.sh` 再次恢复。
9. 输出入口：
   - AstrBot Dashboard：`http://127.0.0.1:6185`
   - NapCat WebUI：`http://127.0.0.1:16099/webui`（token 从 `~/napcat/config/webui.json` 读取，读不到则省略）
   - OneBot WS：`ws://127.0.0.1:<host_port>`
   - NapCat 日志：iTerm 标签 1；AstrBot 日志：iTerm 标签 2。

### `prod.sh stop`

1. 停止生产 AstrBot：
   - PID 文件存在且进程存活：发送 `SIGTERM`，最多等 10 秒；仍存活则报告，不强制 `SIGKILL`。
   - PID 文件不存在但 `6185` 在监听：说明是桌面 App 或其他方式启动，**不杀**，提示用户手动退出。
   - 关闭 AstrBot 标签本身也会停止服务；`prod.sh stop` 用于不开标签或标签已关但进程残留的场景。
   - 停止后清理过期 PID 文件。
2. 停止生产 NapCat：`cd ~/napcat && docker compose stop napcat`（保留容器与数据卷）。关闭 NapCat 日志标签不会停止容器，仍需此命令。
3. 关闭脚本创建的 iTerm 窗口：按 `${HOME}/.astrbot/.prod-iterm-window-id` 关闭对应窗口；窗口已不存在则忽略。随后删除窗口 ID 与 PID 文件，保证下次 `start` 新建干净窗口。
4. 不触碰 E2E 容器、测试 AstrBot；若 `production-stopped` 标记存在，打印提示：稍后 `stop-all.sh` 可能再次恢复生产容器，如不希望可手动删除标记。

### `prod.sh status`

只读输出：

- `docker ps -a` 中的 `napcat`、`napcat-e2e-bot`、`napcat-e2e-sender` 状态；
- `6185`、`6199`、`6186`、`6198`、`13001` 的监听情况；
- 生产 AstrBot PID 文件与进程是否匹配；
- iTerm 窗口 ID 文件是否存在、对应窗口是否仍存在；
- `~/.qq-e2e-docker/production-stopped` 标记是否存在。

## 与现有 E2E 脚本的边界

| 脚本 | 负责 | 不负责 |
|---|---|---|
| `tools/napcat_e2e/start-all.sh` | 启动 E2E 两容器 + 测试 AstrBot；`--stop-production` 停生产并写标记 | 不启动生产 AstrBot |
| `tools/napcat_e2e/stop-all.sh` | 停 E2E 两容器 + 测试 AstrBot；按标记恢复生产容器 | 不停止生产 AstrBot |
| `tools/prod_env/prod.sh` | 启动/停止生产 `napcat` + 生产 AstrBot；启动前自动停 E2E 机器人 | 不管理 E2E 发送者、测试 AstrBot、测试用例 |

共享资源规则：

1. 17号 只能一套在线；`prod.sh start` 自动停 `napcat-e2e-bot`。
2. `production-stopped` 标记由 E2E 写入；`prod.sh start` 成功启动生产后清理过期标记；`prod.sh stop` 不写、不删标记，只提示。
3. `docker compose up -d` / `docker compose stop` / `docker start` 均幂等，重复执行不产生重复容器。

## 风险与回滚

- **自动停 E2E**：用户已确认；若正在跑 E2E 用例会被中断，脚本打印明确警告。
- **AstrBot 桌面 App 与 CLI 冲突**：两者共用 `~/.astrbot` 和 `6185`；脚本发现 `6185` 被占用时跳过启动，并提示可能是桌面 App。
- **SIGTERM 不优雅**：只发 `TERM`，不强杀；必要时用户手动处理。
- **登录态过期**：`wait_onebot.py` 失败时打印 WebUI 地址；本计划不做自动扫码。
- **iTerm2 自动化失败**：AppleScript 报错或未安装 iTerm 时打印手动命令并以非 0 退出；不自动改为 detached，避免产生关终端也不停的进程。NapCat 容器可保持运行。
- **关闭标签的语义**：AstrBot 标签前台运行，关闭即停服务；NapCat 日志标签关闭不影响容器，停容器需 `prod.sh stop` 或 `docker compose stop`。
- **PID 残留**：关标签后 `.prod-run.pid` 可能残留；`prod.sh stop` 会校验进程并清理。
- **窗口 ID 失效**：用户手动关闭窗口后 ID 文件会过期；脚本校验失败时自动新建窗口并覆盖 ID。
- **手动关闭单个标签无法感知**：NapCat 日志标签被手动关闭后，复用窗口时只补 AstrBot 标签；需要重新开 NapCat 日志标签时，删除窗口 ID 文件或执行 `stop` 后再 `start`。
- **回滚**：删除 `tools/prod_env/` 即可；不修改生产 `~/napcat` 配置与 `~/.astrbot` 数据，PID/窗口 ID 文件可手动删除。

## 本轮不做 / 后续阶段（Deferred）

- 自动扫码登录、登录态失效自动通知。
- iTerm2 标签命名、颜色、徽章等个性化设置（用户明确不需要）。
- E2E 脚本自动暂停/恢复生产 AstrBot（现有延期项）。
- 微信等其他平台的启动编排。
