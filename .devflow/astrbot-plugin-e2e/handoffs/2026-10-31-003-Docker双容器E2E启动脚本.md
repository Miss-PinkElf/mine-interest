## 本轮完成

- 新增 `tools/napcat_e2e/`：
  - `compose.yaml`：`napcat-e2e-bot`（17号，OneBot 6200）+ `napcat-e2e-sender`（C#，OneBot 6201）。
  - `start-all.sh`：启动两个容器 + 测试 AstrBot，打开 iTerm 三标签；支持 `--stop-production`、`--restart`、`--force-tabs`。
  - `start-bot.sh` / `start-sender.sh` / `start-astrbot.sh` / `stop-all.sh` / `status.sh`。
  - `wait_onebot.py`：启动 AstrBot 前连接 OneBot 并校验 `get_login_info.user_id`。

- 启动 AstrBot 的健壮性：
  - 先等待 6200/6201 且账号真正就绪；
  - `start-instance` 失败自动重试 3 次（间隔 3 秒）；
  - `--detach` 后台启动，关闭终端一般不会停；
  - `--restart` 先停旧实例/重启容器再启动。
- iTerm AppleScript：
  - iTerm2 3.6.7 的应用名是 `iTerm`，不是 `iTerm2`；
  - 改为 `tell application "iTerm"`，编译通过并实跑打开三标签。

## 已知问题与处置

| 问题 | 原因 | 处置 |
|---|---|---|
| `Server disconnected` | NapCat 刚重启/重连，端口已开但账号 WS 未稳定 | `wait_onebot.py` + 重试 + `--restart` |
| iTerm 不弹窗 / `-2741` | AppleScript 应用名写成 `iTerm2` | 改为 `iTerm` |
| `probe_echo` 失败 | 测试实例同时加载 cc-qq 与 probe | probe-only 测试根 / 测试群禁用 cc-qq |
| `/info` 断言失败 | 用例断言过期（期望 `/new`） | 改为包含「当前会话」或匹配「状态」 |
| 生产容器与 E2E 抢 17号 | 同一 QQ 不能双端在线 | `--stop-production` + `stop-all.sh` |
| 进容器 `kill` QQ 不可靠 | entrypoint 无守护进程 | 用 `docker restart` / `compose restart` |
