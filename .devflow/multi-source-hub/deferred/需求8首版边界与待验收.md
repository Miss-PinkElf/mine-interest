# 需求 8 首版边界

## 已实现

- 采集内容中的 GitHub 仓库链接自动 star。
- 有权限的 QQ 发送者、B 站触发评论含 `/fork` 时自动 fork。
- fork 内安装 `.github/workflows/sourcehub-fork-sync.yml`，每 6 小时只合并默认分支。
- `gh` 直连失败且属于网络错误时，用 `http://127.0.0.1:7897` 重试一次；权限/未登录不重试。
- QQ 成功/失败都回复；B 站写日志和插件页最近动作。
- B 站插件页实时校验 Cookie，失效红色提示。

## 本轮暂不做（Deferred Scope）

1. **QQ 合并转发内层链接**
   - 暂不做对象：合并转发消息内部包含的 GitHub 链接。
   - 原因：转发内容可能来自无权限的人，首版避免越权触发外部副作用。
   - 后续触发条件：用户明确要求转发内链接也生效，且需要先定义权限归属。
2. **fork 与上游冲突自动解决**
   - 暂不做对象：merge 冲突时的自动 rebase/取舍。
   - 原因：自动解决冲突风险高，可能破坏 fork 本地提交。
   - 后续触发条件：出现真实冲突且用户要求自动处理。
3. **私有上游仓库的 fork 同步**
   - 暂不做对象：上游为私有仓库时的 `git fetch upstream` 凭据。
   - 原因：Actions 内需要额外的访问凭据，首版只保证公开仓库。
   - 后续触发条件：真实 fork 私有仓库。
4. **同步频率配置化**
   - 暂不做对象：每 6 小时之外的频率配置。
   - 原因：首版先用固定 cron，避免配置项与已安装工作流不一致。
   - 后续触发条件：用户要求调整同步频率。
5. **取消 star / 管理收藏夹、fork 后自动提 PR**
   - 暂不做对象：收藏管理与贡献流程自动化。
   - 原因：超出需求 8 的“自动 star/fork + 同步”范围。
   - 后续触发条件：用户另行提出。
