# QQ 与 B 站获取消息的能力边界

两套插件职责不同，不要混用。

| | QQ 检查插件（Message Inspector） | B 站只读采集（Read-only Mention Collection） |
| --- | --- | --- |
| 插件 | `astrbot_plugin_sourcehub_inspector` | `astrbot_plugin_sourcehub_bilibili` |
| 入口 | 群里实时推送（OneBot v11 / NapCat） | 轮询「收到的 @」（`/x/msgfeed/at`） |
| 现在做什么 | 整条事件快照 + 合并转发展开 | 保存 @ 评论、父/根评论、作品正文和图片 |
| 不做什么 | 不回复、不正式收藏、不下载媒体 | 不公开回复、不扫码登录、不下载视频文件 |
| 数据目录 | `data/sourcehub-inspector/` | `data/plugin_data/astrbot_plugin_sourcehub_bilibili/<mid>/` |

平台前提：QQ 走 **个人号 NapCat**，官方 QQ 机器人没有 `get_forward_msg`。B 站必须在本插件配置里填本地 `SESSDATA` 并打开 **启用只读采集**。

## 一、QQ：能拿到什么

检查插件监听 AstrBot 收到的群消息。

**已经能拿到（2026-09-20 已实测）**

- 群聊普通文本、@、图片段的 **元数据**（`file` / `url`，URL 含 `rkey`）
- 合并转发（Forward）的内层树：发送者 QQ / 昵称 / 群名片、时间、消息 ID、群 ID、`text` / `image` 等段
- 嵌套转发：优先用内联 `content`，缺失才按 id 补取（再按 id 可能 `retcode 1200`）
- 实测样例：3 层 / 35 条 / 157 图 / 19 文本
- 群白名单：`enabled_group_ids` 留空=全部群；填了只处理列出的群

**拿得到事件、但没有做成「可离线原文」**

- 图片、表情、语音、视频：JSON 里有 URL，**插件不下载**。腾讯 CDN 的 `rkey` 会过期，晚了就打不开
- 顶层直接发的图、转发里的图，都还没自动落盘

**当前拿不到或不可靠**

- 机器人自己发出的消息：NapCat 侧可能没上报到 AstrBot（配置写了 `reportSelfMessage=true`，运行实例疑似未生效）。需重启 NapCat 后再看
- 个别转发：`get_forward_msg` 返回空数组，插件标「未展开」，不是插件逻辑错误
- 超过 5 层的嵌套：截断并写 `_sourcehub_truncated`
- 白名单开启后的 **私聊**：不处理
- 日常群「按规则筛选再收藏」：延期，检查插件只是诊断快照，不是正式收藏

**明确不做（本阶段）**

- 自动回复
- 指定日常群持续筛选入库
- 快照自动清理
- 把整份 `event`（含 bot/平台对象、`rkey`）当正式档案提交 Git

## 二、B 站：能拿到什么

只处理 **别人 @ 了采集号** 的通知，不是全站爬取，也不是自己发的所有评论。

**已经能拿到（2026-09-21 已实测，状态完整）**

| 样本 | 结果 |
| --- | --- |
| 视频顶层 @ | 触发评论、视频标题、页面链接、简介 |
| 回复根评论 @ | 触发 + 父评论 + 根评论（此时父=根） |
| 回复子评论 @ | 触发 + 父评论 + 根评论（父 ≠ 根，已核对） |
| 专栏顶层 @ | 标题、`/read/cv…` 链接、专栏全文 |
| 图文动态顶层 @ | 正文 + 本地图片（修过空 `module_content` 后已完整） |

另外已确认：

- 登录 Cookie 只打 B 站 API，图片用独立无凭证会话
- 完整条目不再覆盖；部分条目按字段合并补齐
- 默认 120 秒轮询；当前扫描接口还能看见的历史 @ 会在首次启动时收入
- **不下载视频文件**，只保存可交给下载器的页面链接和简介

**能力边界（设计如此，不是漏测）**

- 只扫 `@` 通知，不扫私信、点赞、回复我的、弹幕、收藏夹
- 自己 @ 自己，常常进不了「收到的 @」，要用第二个号发
- 没有发送者白名单：谁 @ 都会采
- 没有扫码登录、没有 Cookie 自动刷新；过期后只会记 `login_required` 这类错误类别
- 不承诺平台已经不再返回的更早历史
- 未知正文节点会保留原始 JSON，标部分（Partial）
- 专栏/图文里的超大图受 `media_max_bytes`（默认 50 MiB）限制，超限记缺口、不换成缩略图

**代码有、真实账号还没覆盖的**

见下一节「建议你测」。

## 三、建议你测的清单

下面都可以在不改代码的前提下测。测完说一声样本类型和大约时间即可，**不要把 Cookie、SESSDATA、完整快照发到聊天**。

### B 站（优先，采集已经在跑）

发完最多等一轮轮询（默认 120 秒），然后看：

`~/.astrbot/data/plugin_data/astrbot_plugin_sourcehub_bilibili/<mid>/items/`

对应 `content.md` 应为完整，图片在 `media/` 里能打开。

| 编号 | 怎么发 | 用来确认什么 |
| --- | --- | --- |
| B1 | 专栏评论区里 **回复某条已有评论** 再 @ | 专栏场景下父/根评论是否也分得清 |
| B2 | 动态评论区里 **回复子评论** 再 @ | 动态是否也能保存父 ≠ 根 |
| B3 | @ 一条 **转发动态**（带附言的那种） | 附言 + 原动态是否都在（离线有测，线上还没有） |
| B4 | @ 一条 **纯图片动态**（几乎没字） | 图下载成功后应标完整，不能只因没字失败 |
| B5 | 评论里带 **表情包/评论配图** 再 @ | 评论区图片会不会进 `media/` |
| B6 | @ 一条 **分 P / 合集视频** | 简介和分集信息是否留下，且仍不下载成片 |
| B7 | @ 后立刻 **删掉那条评论** | 应变成部分并留下缺口，不能假装完整 |
| B8 | 用 **过期或错误 SESSDATA** 重载一次，再改回正确值 | 日志应是登录类错误而不是把 Cookie 打出来；改回后能恢复 |
| B9 | 同一条 @ 等到下一轮轮询 | 完整条目的 `content.md` 不被覆盖 |
| B10 | 发一条后拔网 / 等 DNS 失败再恢复 | 通知还在，恢复后能补成完整 |

B1、B2、B3 最有价值。B7 会留下一条 Partial，属于预期。

### QQ（检查插件）

在启用范围内的群发，看日志 `[SourceHub Inspector]` 和 `data/sourcehub-inspector/`。

| 编号 | 怎么发 | 用来确认什么 |
| --- | --- | --- |
| Q1 | **重启 NapCat** 后，用机器人号在群里发一句带唯一标记的话 | 自身消息会不会出现快照。这是 QQ 最大的未闭环项 |
| Q2 | 群里直接发一张图（不转发） | 快照有没有图片段；确认仍 **没有** 本地文件（当前边界） |
| Q3 | 语音、短视频、文件、小程序卡片、回复引用 各一条 | 事件里有哪些段类型；哪些只有占位 |
| Q4 | 4 层或 5 层嵌套转发，内外层都写独特文字 | 能否展到第 5 层；第 6 层应截断 |
| Q5 | 找一条以前「点开是空白」的合并转发再发一次 | 是否仍返回空，便于和插件 bug 区分 |
| Q6 | 填了群白名单时，从 **未列出的群** 和 **私聊** 各发一条 | 不应落盘 |
| Q7 | 同一条消息（或同一转发）快速重发 | 现在可能存两份快照；正式去重还没做 |

Q1 请先做：不用改插件，只重启 NapCat 再看机器人自己的那句话有没有快照。

## 四、测的时候怎么看有没有成功

**B 站**

- 日志不应再是「未启用采集」
- `items/<通知编号>/content.md` 第一行是 `complete` 或带「未完成项」的 `partial`
- 视频应有 `https://www.bilibili.com/video/BV…` 和简介
- 专栏应有 `/read/cv…` 和长正文
- 动态应有正文或本地图片，不应只剩链接
- 父/根：顶层两者都是「没有」；回根评论时父=根；回子评论时两条编号和正文都不同

**QQ**

- 普通消息：`data/sourcehub-inspector/snapshots/` 多一份 JSON
- 转发：`forwards/` 下同时有 `.json` 和 `.txt`，txt 里有层数 / 条数 / 段类型
- 自身消息：若 Q1 成功，快照发送者应是机器人 QQ；若仍没有，继续记在延期项 D-SELFSG

不要把 Cookie、`rkey` 完整 URL 清单、真实快照提交到 Git 或贴进对话。说「发了 B3 转发动态」或「重启 NapCat 后自身消息仍没有」就够。

## 五、和总目标的关系

多源信息中心的「指定日常群筛选收藏、自动下载视频、扫码登录」都还没做。本文只描述 **现在这两套插件实际能取到的消息边界**。QQ 媒体落盘、自身消息、事件去重仍是延期，不是测试通过就会自动开工。
