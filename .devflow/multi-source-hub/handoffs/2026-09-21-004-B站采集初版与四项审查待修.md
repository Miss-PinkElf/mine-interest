# 四个必须先修的问题

来自独立审查代理 `bilibili_review`，已由其在临时目录用合成数据复现。主代理本次核对相关代码仍未修改；回归案例尚未加入现有测试。

## P1：部分归档重试丢失原文

- 现象：首轮正文成功、图片失败；次轮正文接口失败，旧全文及 `raw.objects` 被空结果覆盖。
- 原因：`store.py:save()` 只保护完整状态（Complete），部分状态（Partial）直接覆盖 `content.md` 和 `record.json`。
- 解决要求：保留已获取原文，可按分支合并成功结果，或保留不可变尝试快照（Attempt Snapshot）；选择最小可靠方案。不能把 Partial 直接视为 Complete。
- 具体方案尚未决定；主代理仅考虑过快照，未实施。
- 验收：首轮正文有唯一标记且图片失败，次轮正文报错，旧正文和原始对象仍可读取；后续成功重试可完成。快照方案须验证图片相对路径和相同版本去重。

## P1：单条异常阻塞后续通知

- 现象：首项抛属性错误（AttributeError），后续正常通知连续多轮不处理。
- 原因：`poller.py:process()` 只捕获 FetchError/ValueError/TypeError/KeyError；链式 `.get()` 遇 null 可抛 AttributeError，失败项未更新 attempted_at，始终排前面。
- 解决要求：单条边界隔离普通异常，保存安全错误类型并继续后续项；取消异常（CancelledError）必须传播。修正已知 null 访问，不能仅吞异常。
- 验收：首项 `desc=None` 或抛 AttributeError，第二项正常；第二项同轮完成，第一项保留可重试状态；取消任务不会被吞掉。

## P2：空正文永久标为完整

- 现象：专栏 `content='{"ops":[]}'`、图文段落 `text.nodes=[]`、HTML `<div></div>` 可返回空文且 gaps=[]，随后 Complete，不再重试。
- 原因：只检查字段/段落存在，没有验证渲染后正文。
- 解决要求：在正文层验证实际文本或图片；不能用标题、通知、来源链接证明全文存在；纯图片正文可以合法成功。
- 验收：三类空正文均 Partial，纯图片正文下载成功可完成；未知节点继续保留原始响应并标缺失。

## P2：缺失关系等同没有父评论

- 现象：响应仅有评论编号/正文，缺 parent/root，得到 parent=None、root=None、gaps=[]。
- 原因：`collector.py` 用 `.get(...) or ''` 合并了缺失和明确零值。
- 解决要求：区分平台明确无父评论与关系字段未知；后者 Partial。兼容字符串/整数编号，不用根评论替代直接父评论。
- 验收：明确零值的顶层评论成功；字段缺失/null 明确缺失；子评论父/根分别匹配编号。
