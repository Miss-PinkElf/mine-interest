# 019：GitHub star 列表归类

## 需求与决策

自动 star 时把仓库加入配置的 GitHub Lists；未配置、名称不匹配或查询失败时仍完成普通 star。已确认：

- 只对**本次新 star** 生效，已 star 的仓库不移动；
- 加入目标列表时**保留其他列表**（并集）；
- 列表按**名称完全匹配**；
- 找不到列表时正常 star，回复说明「放入默认位置」；
- 加入列表失败时 star 仍保留，动作标记失败并说明。

## API 结论

- REST `/user/lists` 返回 404，GitHub 没有公开 REST Lists 接口。
- GraphQL 可用：
  - `viewer.lists` 读取列表与条目；
  - `updateUserListsForItem(input: {itemId, listIds})` 设置条目归属；
  - `repository(owner, name) { id }` 获取仓库 node id。
- 仍通过 `gh api graphql` 调用，不引入新依赖。

## 实现

- 共享库 `sourcehub/github_actions.py`：
  - `GithubAutomation(state_path, runner, star_list="")`；
  - `_graphql`、`_assign_star_list`；
  - 列表查询同时读取仓库 node id、目标列表与各列表条目；
  - 列表数或单列表条目超过 100 时放弃归属，避免误删手动归属；
  - `listIds` 只接受 `UL_` 开头的合法 ID。
