# 目标（Goal）

1. 修掉日文档「实时消息（Live Messages）」区的多行截断：多行 QQ 消息到达时，摘要行不再只剩最后一行。
2. 订正 2026-10-15 已经写坏的摘要行（全库复扫确认仅此 1 条）。
3. 补一份 QQ 群消息采集链路说明文档，把「配置 → 采集 → 成条 → 落盘 → 媒体 → 整理 → 发布」讲清楚。

# 架构（Architecture）

缺陷在**渲染分层**：`append_daily_message` 需要「消息正文」，却用 `render_content_md(envelope).splitlines()[-1]` 从**整篇 Markdown** 里抠最后一行。整篇 Markdown = 封套头部元信息 + 正文，抠最后一行在单行消息下偶然成立，多行消息下必然截断。

修法是把「头部元信息」与「正文」在渲染层显式拆开，让摘要有正确的取用点；再让日文档把正文按「首行跟 bullet、其余行缩进续写」投影。不引入猜测式启发（例如「跳过所有以 `- ` 开头的行」会误伤以列表开头的消息）。

# 根因（Root Cause，已确认）

证据链：`backend.log` 22:10:15 收到单条群消息 → `spool/qq_daily/836229427/2026-10-15.json` 存有完整 204 字原文 → 在 Vault 副本上用真实代码复现 `render_content_md(env).splitlines()[-1]`，输出正好等于 `content.md` 里那一行。

| 位置 | 事实 |
| --- | --- |
| 缺陷代码 | `integrations/astrbot/astrbot_plugin_sourcehub_inspector/sourcehub/vault.py:106`（`backend/src/sourcehub/vault.py:106` 同源） |
| 缺陷语句 | `current += f"\n- \`{envelope.event_id}\` {render_content_md(envelope).splitlines()[-1]}\n"` |
| 触发条件 | 消息正文含换行（`\n`）。单行消息不受影响，所以 2026-09-22 ~ 09-30 一直未暴露 |
| 影响面 | 全库复扫「日文档摘要行 vs 日账本原文」，**仅 2026-10-15 的 `1441885612` 1 条** |
| 是否丢数据 | 否。日文档是索引+摘要，不是真相源；完整原文在日账本与成条后的 Item 里 |

补充结论（本轮不改，记录备查）：普通消息走日账本分支时不 `upsert`，因此 `items/qq/2026-10-15/` 下暂无 `message/` 子目录；`@整理` 或午夜调度成条后即出现。这是 2026-09-22 的既定设计。
