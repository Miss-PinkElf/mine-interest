# 检查插件群级启用范围计划

## 一、问题

- 插件当前对所有群生效。2026-09-20 一天产生 402 份快照，其中绝大多数不是收藏群，属于噪音。
- 日志只有快照路径，没有群标识，无法一眼确认「这条属于哪个群 / 哪些群在生效」。
- 交接与 README 都把「来源白名单」列为已知缺口，本轮补上。

## 二、目标

1. 只对配置的群保存快照和展开转发。
2. 插件加载时把启用范围写进日志。
3. 每条处理日志带上群名与群号。

## 三、方案（最小改动）

1. 新增 `_conf_schema.json`（AstrBot 插件配置 schema，WebUI 插件配置页可直接编辑）。
2. `main.py.__init__` 改为接收 AstrBot 注入的 `config`，解析群白名单并在加载日志中打印启用范围。
3. `inspect_message` 开头做启用判断：不在范围内的群直接返回，不落盘、不展开（跳过记 `debug`，避免刷屏）。
4. 日志行统一带上 `群名(群号)`。

### 关键决策

| 决策点 | 选择 | 理由 |
| --- | --- | --- |
| 白名单留空的含义 | **全部群启用** | 保持现有诊断行为不变，避免改完突然收不到消息；显式填了才收窄 |
| 匹配方式 | 统一转字符串去空白后比对 | 群号在事件里是字符串，用户在配置页可能填数字 |
| 非白名单群 | 直接跳过（debug 记录） | 诊断阶段不需要噪音，也不影响其他插件 |
| 配置载体 | `_conf_schema.json` | AstrBot 官方插件配置机制，复用现成能力而不是自己读文件 |
| 是否加群内命令开关 | 本轮不做 | 先用配置；命令式开关等范围稳定后再评估 |

## 五、验证方式

1. 覆盖本机插件目录，WebUI 重载。
2. 加载日志应打印启用范围；白名单留空时应明确显示「全部群」。
3. 填一个群号后重载，只有该群的消息产生快照，其他群不产生新快照。
4. 处理日志能看出群名与群号。

## 六、本轮不做（Deferred Scope）

- **媒体持久化**、**快照脱敏**、**事件身份修复**：沿用上一轮计划，仍为待办。
