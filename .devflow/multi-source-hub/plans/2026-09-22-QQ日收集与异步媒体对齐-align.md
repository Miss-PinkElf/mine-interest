# QQ 日收集、异步媒体与 B 站 Markdown 对齐

## 已确认目标

1. QQ 每个群按北京时间（Asia/Shanghai）维护一份当天持续扩充的日收集文档（Daily Collection Document）。
2. 普通消息先进入日收集文档；合并转发（Forward）始终单独成一条 Item（资料条目）；`，，，` 至 `。。。` 的会话（Session）始终单独成一条 Item。
3. 每日 00:00 自动整理前一天尚未整理的普通消息。用户发送 `@bot 整理` 时，立即整理当天尚未整理的普通消息。
4. 手动整理与定时整理必须复用同一整理器（Single Finalizer），以稳定 `message_id` 与已处理游标（Processed Cursor）保证不重复成条。
5. 会话收口不再同步下载大量图片。条目先写入，图片转为持久媒体任务（Media Job），由后台受限并发下载后回写哈希媒体库（Hash Media Store）。
6. B 站专栏（Article）和动态（Opus）重新渲染为结构化 Markdown；已有本地 B 站档案可重新导出到 Vault（资料库）。

## 方案选择

采用“持久化日收集账本 + 单一整理器”方案。内存暂存无法跨插件重启恢复；先为每条普通消息创建 Item 再合并会留下大量无意义中间条目，均不采用。

## 数据流

```text
QQ 普通消息 -> 当日账本追加 -> 手动 @bot 整理 / 00:00 定时 -> 单一整理器 -> Item
QQ 转发或标记会话 -> 既有成条规则 -> Item
Item 图片 URL -> 媒体任务队列 -> 后台受限并发下载 -> Vault media/ + Item 回写
B站已存档 -> 结构化 Markdown 投影 -> Vault 回填
```

## 验收

- 00:00 与 `@bot 整理` 任意先后执行，都只为同一普通消息生成一次 Item。
- 插件重载后，未整理的日收集消息仍可继续整理。
- 大量图片下载期间，QQ 事件处理和 B 站轮询可继续运行。
- 专栏、动态 Markdown 保留标题、正文块、图片与来源链接的可读顺序。

## 本轮不做 / 后续阶段

- 不做知识整理（Knowledge Organization）、自动标签或模型判断；本轮只收集与成条。
- 不改动外层 14 项正式规格；触发条件是用户另行确认整体信息中心范围。
- 不自动提交开发仓库；如完成代码修改后，需先询问用户是否提交。
