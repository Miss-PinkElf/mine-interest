# 多源信息中心：成条与原始资料落盘对齐

## 1. 本轮要解决的问题

QQ 检查插件已能展开嵌套转发；B 站只读采集已能把五类 @ 存成档案。两套插件各自一种落盘形状。本轮把「已经抓到的东西」收成同一种资料条目（Item），让人能打开 Markdown 阅读原文，让程序能按稳定身份合并和去重。

本轮做第一层捕获与归一（Capture / Normalize）和第二层成条（Grouping）。第三层知识整理（Organize：标签、摘要、维基）不做。大语言模型（LLM）不参与切块、下图、合并作品。

## 2. 已确认方向

- 先成条，再知识整理。输出是统一条目，不是标签页。
- 结构里留下判断槽（Judge Slot），首期关闭直通。日常群的规则/正则/模型筛选以后填进准入（Admit），不另做一套引擎。
- 每个来源挂一份规则包（Rule Pack），顺序固定：准入 → 成条 → 媒体 → 判断。
- 原始资料两层：`envelope.json` 是结构真相源；`content.md` 是给人看的原文投影。每个条目一对文件。
- QQ 与 B 站共用一份入库库（Capture Library）和一份资料目录（Vault）。不上完整信息中心 14 项服务。
- 知识数据与代码仓库分开。Vault 同时是独立 Git 仓库，远端可以是 GitHub 或 Gitee 私有库。本轮本地提交；自动推送默认关。
- 图片默认落地；视频只留页面链接；单文件默认上限 50 MiB；本轮不做自动清理。

## 3. 规则包（Rule Pack）

| 段 | 首期 QQ 收藏群 | 首期 B 站 |
| --- | --- | --- |
| 准入（Admit） | 配置的收藏群内到达的消息都进 | 收到的 @ 才进 |
| 成条（Group） | 见第 5 节 | 见第 6 节；无会话标记 |
| 媒体（Media） | 图片下载；视频只留链接；超上限记缺口 | 同左；B 站配图下载，视频成片不下 |
| 判断（Judge） | `enabled=false`，原样放过 | 同左 |

规则默认值写在入库库。群号、SESSDATA、是否启用仍在各 AstrBot 插件配置。标记名、空闲超时、体积上限、Git 远端 URL 放在资料根的来源配置里，跟着知识仓库走。

判断槽配置可以写类型和开关。首期执行器看到关闭就跳过，不调用模型，不丢原文。

## 4. 捕获封套（Capture Envelope）

沿用 2026-09-09 规格中的封套方向，本轮补上「多条合成一条」与「按作品合并」。

| 字段 | 作用 |
| --- | --- |
| `schema_version` | 封套版本，未知版本拒绝 |
| `platform` / `conversation_id` | 平台与会话（QQ 群、B 站账号维度） |
| `item_id` | 资料身份，见下表 |
| `event_id` | 触发本次写入的平台事件；会话/作品条目另用成员事件列表 |
| `sender_id` | 投递者。转发内层原作者在子节点 |
| `source_time` / `received_at` | 来源发送时间可空；接收时间必有。会话条用第一条成员消息的来源时间 |
| `content` | 有序节点：`text` / `image` / `file` / `quote` / `forward` / `unknown` |
| `attachments` | 附件清单与落地状态 |
| `gaps` | 缺口列表 |
| `grouping` | `single` / `merged_forward` / `session_markers` / `work_object`，以及成员事件 ID |

`item_id`：

| 形态 | `item_id` |
| --- | --- |
| QQ 单条消息 | 该群消息 ID |
| QQ 合并转发 | 收藏群里那条转发的消息 ID |
| QQ 会话 | `session:` + 开始那条消息 ID |
| B 站视频 | `bilibili:video:<bvid>` |
| B 站专栏 | `bilibili:article:<cvid>` |
| B 站动态 | `bilibili:opus:<dyn_id>` |

逻辑 `item_id` 用上表字符串。目录按 `/` 分段，例如 `items/bilibili/video/<bvid>/`，避免路径里出现冒号。QQ 身份必须用平台消息 ID，不能回退成接收时间（已知检查插件有过该问题，本切片入库时要钉死）。

未知内容节点原样保留。模型只读封套和媒体的稳定引用，不读 `private/events/`。

## 5. QQ 成条

收藏群继续「转发即收藏」，不需要 @ 机器人。会话标记是额外的成条规则，和转发即收藏并存。

会话标记：

- 默认开始：整句等于三个中文逗号 `，，，`
- 默认结束：整句等于三个中文句号 `。。。`
- 去掉首尾空白后整句精确匹配。句子中间或末尾带着 `。。。` 不算结束。
- 标记名可配置。默认不把英文 `,,,` / `...` 当成同一标记。
- 开始句和结束句只当边界，不写进条目正文。

| 情况 | 行为 |
| --- | --- |
| 普通一条（无标记、非转发） | 一条消息 = 一条资料 |
| 合并转发 | 一份转发 = 一条，内层当 `forward` 子节点 |
| `，，，` … `。。。` | 中间消息按顺序进同一条 |
| 会话里再来一份转发 | 当该条的子块，不另开一条 |
| 会话里的图 | 下到这条的附件上 |
| 开着会话时又来一句 `，，，` | 上一份按未结束收口并记缺口，再开新会话 |
| 没有开着的会话时来一句 `。。。` | 不当结束符，也不单独存成一条 |
| 转发内部的 `，，，` / `。。。` | 只当转发正文，不触发外层成条 |
| 缺结束 | 空闲超时后仍保存已收到内容，记 `session_end_missing` |
| 空闲超时 | 可配置，默认 30 分钟，从最后一条成员消息算起 |
| 会话范围 | 按整个收藏群共用一份开着的会话，不按发送者拆 |
| 插件重载 | 未关闭缓冲先落到 `spool/`，起来后按原 `item_id` 接着收 |

展开转发继续用现有 `get_forward_msg` 路径。诊断快照可另写 `private/events/`，不替代封套。

## 6. B 站成条

B 站规则包没有会话标记，也没有空闲超时。一次 @ 采集作品和评论，按**作品**合并成一条。

| 你在哪 @ | 这一条里保存 |
| --- | --- |
| 视频下（顶层） | 视频页面链接、简介，加上这条 @ 评论 |
| 某条评论下面 | 上面那些，再加上这条评论；若有上一级/根评论，一并挂上 |
| 专栏 | 专栏全文，加上 @ 评论及上一级（若有） |
| 动态 | 动态正文和配图，加上 @ 评论及上一级（若有） |

同一视频、动态或专栏上的多次 @（包括不同评论层）都并进这一条，评论挂在作品下面。作品本身只保存一份。之后再 @ 同一作品：打开已有条目，把新评论节点加进去。同一个 `rpid` 再出现则更新该节点。隔几天再 @ 同一个视频，仍进那一条。

父评、根评是这条的上下文节点，不是另外的收藏条目。采集方式保持只读：不自动公开回复，不下载视频成片，不在本轮做扫码登录或发送者白名单。

## 7. 原始资料两层与资料目录

数据根可配置，默认建议 `~/.astrbot/data/sourcehub/`，也可以直接指向已克隆的私有知识仓库。不进 `mine-interest` 代码仓库。

```text
<vault>/
  items/<item_id>/envelope.json    结构真相源
  items/<item_id>/content.md       可读原文，由封套生成
  media/<sha256>                   图片等字节，按内容哈希去重
  spool/                           QQ 未结束会话、待下完的图
  private/events/                  平台原包（可能带 rkey），不给模型、不进远端
  catalog.sqlite3                  身份索引：作品 ID / 会话 ID → item_id
  sources/*.yaml                   来源规则与远端 URL
```

`content.md` 含来源、时间、缺口、正文/作品、评论或成员消息、指向 `media/` 的相对图片链接。条目有更新（同一视频又 @、会话又多了一句）就从封套重生成这一篇，与 JSON 保持一致。

本轮 Markdown 是可读的原文，不是标签、摘要、维基。用户以后改原文，走「用户改原始资料」入口，写回封套再生成 MD。本轮不把手工改 MD 当作真相源。

检查插件旧快照、B 站旧 `record.json` 继续留在原插件数据目录当档案。新收藏写入 Vault。不删除已有私人归档。

## 8. 媒体

这是此前延期项「媒体落盘」中**图片默认落地**的进入条件：体积策略已确认。

| 类型 | 行为 |
| --- | --- |
| 图片（含转发内层、B 站配图） | 默认下载；按字节哈希去重；多条资料可指向同一文件 |
| 视频 | 只留页面链接，不下成片 |
| 单文件上限 | 可配置，默认 50 MiB；超限记缺口，条目仍保存 |
| 扩展名 | 按内容魔数判断 |
| QQ 图 | 收到就下（`rkey` 会过期）；腾讯 CDN 走直连 |
| 失败 | 记 `media_failed`，条目保持部分（Partial），可重试 |
| 自动清理 | 本轮不做 |

语音、表情是否落地：能拿到的图片按图片走；拿不到的记缺口。不把未确认的类型假装下完。

## 9. 独立知识仓库（Git）

Vault 是独立 Git 仓库，与代码仓库分开。

| 进 Git | 不进 Git |
| --- | --- |
| `envelope.json`、`content.md`、来源配置中的非密钥部分 | `private/events/` |
| 条目元数据 | `spool/` |
| | Cookie、SESSDATA、登录态 |
| | 视频成片 |

图片首期本机保存，不进普通 Git。以后要远端也有图，再用 Git LFS 或单独媒体库，做成开关。

提交粒度：一条资料一次本地提交，说明含 `item_id`。Git 提交失败时文件已写，记待提交，不回滚原文。

远端地址可配置（GitHub 或 Gitee 私有库）。自动 `git push` 默认关。用户建好空库、填上远端、确认没有凭证和原包后再打开。未经授权不把私人收藏推进代码仓库或任何远端。

## 10. 插件与入库库

QQ 和 B 站仍是两个 AstrBot 插件，共用一份入库代码。建议放在 `backend/src/sourcehub/`（封套、规则包、Vault、媒体、本地 Git），安装时打进两个插件都能导入的包。

收消息的进程里当场下图、当场写条目。QQ 不把图片下载推迟到夜间批处理。

```text
QQ 收藏群消息
  → 检查/收藏插件（展开转发）
  → 规则包（判断关闭）
  → 入库库 → items/ + media/ + catalog + 本地 Git

B 站 @ 轮询
  → 现有只读采集插件
  → 规则包（按作品合并，判断关闭）
  → 同一个入库库
```

QQ 在现有检查插件上长出正式收藏：收藏群、规则包、图片落盘、写入 Vault。B 站少改采集逻辑，改存储：按作品 `item_id` 合并进封套。

## 11. 失败行为

| 情况 | 行为 |
| --- | --- |
| 图下载失败 / 超 50 MiB | 条目保存，记缺口，可重试 |
| 转发未展开 | 条目保存，记 `forward_unexpanded` |
| 会话超时没等到 `。。。` | 已收到的仍落成一条，记 `session_end_missing` |
| 同一 QQ 事件重放 | 同一 `item_id`，不新建 |
| 同一 B 站作品再次 @ | 合并进已有条目 |
| Git 提交失败 | 文件已写；记待提交 |
| 判断槽关闭 | 直通，不调用模型 |
| 封套未知版本 | 拒绝写入，保留 spool |

## 12. 本轮做 / 不做

**做**

- 统一捕获封套与规则包结构（判断槽预留、关闭直通）
- 入库库、共用 Vault、身份索引
- QQ：转发成条、会话标记、图片落盘
- B 站：现有采集映射进封套，按作品合并多次 @
- 每个条目生成 `content.md`
- 本地 Git 提交；可填私有远端（默认不自动推）

**不做（延期，不是放弃）**

| 对象 | 原因 | 后续触发 |
| --- | --- | --- |
| 标签、摘要、维基等知识整理 | 先成条 | 统一条目跑通、用户要整理时 |
| 判断槽真正执行 / 模型辅助判断 | 结构先留槽 | 用户要开判断时另写计划 |
| 日常群规则/正则/模型筛选 | 仍按 2026-09-09 延期 | 主动收藏成条验收后，填准入段 |
| 完整 14 项核心（HTTP API、MCP、四角色、Git 协调器） | 先薄存储 | 条目契约稳定后再铺服务 |
| 自动 `git push`、Git LFS | 先本地、图先本机 | 用户建好私有库并确认无密钥后 |
| B 站下视频、扫码登录、发送者白名单 | 首版边界不变 | 用户单独要求时 |
| 快照/媒体自动清理 | 体积策略本轮只定上限 | 与清理策略一起设计 |
| 机器人自身消息 | 仍等 NapCat 复测 | 重启后若仍不上报再选回填方案 |

既有延期真相源继续有效：`deferred/QQ指定群持续收集与规则筛选.md`、`deferred/媒体落盘与机器人自身消息.md`（其中图片落地由本稿接入，清理与自身消息仍延期）、`deferred/B站首版未做与可选实测.md`。

## 13. 验收

离线（`backend/.venv`）：

1. QQ 单条、合并转发树、`，，，`…`。。。` 会话、缺结束超时，各生成一个条目和一篇 `content.md`。
2. 会话标记整句匹配：正文为「好的。。。」的消息不成结束符。
3. B 站同一视频两条不同评论 @，只有一个 `item_id`、一篇 `content.md`，两条评论都在里面；专栏/动态同样按作品合并。
4. 图片哈希去重、超 50 MiB 记缺口、视频节点只留链接。
5. 重放同一 QQ 事件不新建条目；B 站同一 `rpid` 更新原节点。

真实联调（实现之后，由用户新发）：

- QQ 收藏群：普通图文、一份合并转发、一段 `，，，` … `。。。`。
- B 站：同一视频下两条不同评论里 @，确认一篇 MD 里有两条评论。

实现前用户新发的 @ 和群消息，仍由现有插件按旧形状保存，可当样本，不作为本切片正式验收。不得要求在聊天里粘贴 Cookie 或私人正文。
