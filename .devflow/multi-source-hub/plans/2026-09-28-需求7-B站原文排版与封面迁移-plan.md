# 需求 7：B 站原文排版与封面迁移 Implementation Plan

> **面向实施者（For agentic workers）**：按本 mission 的 `tasks.md` 顺序执行；每个任务验证后再继续。用户已授权 Plan 后进入 Apply，并在 2026-09-28 收尾时明确授权提交本次相关代码。

**实施快照（Implementation Snapshot）：** 结构化投影、封面入口、评论合并、迁移工具和离线测试已完成；真实 Vault 尚未重渲染。当前任务勾选与验收证据以 `spec/2026-09-28-需求7/tasks.md` 为准，未完成的真实迁移见 `deferred/需求7首版边界与真实验收.md`。

**目标（Goal）：** 使视频、专栏、动态的 `content.md` 忠实呈现结构化原文、评论关系和本地媒体，并安全重渲染已有 B 站条目。

**架构（Architecture）：** 原始采集记录（Raw Record）保留为输入；B 站专用投影（Bilibili Projection）从结构化作品、评论与媒体映射生成可读 Markdown，`envelope.json` 保存可再生成的必要字段。资料目录（Vault）仍负责原子写入与索引，QQ 渲染路径不变。源 JSON 没有格式标记时保留原样，不调用大语言模型（LLM）判断排版。

**技术栈（Tech Stack）：** Python、AstrBot 插件、`backend/src/sourcehub/` 共享库、`unittest`、SQLite catalog、现有 Vault 媒体目录。

## 实施步骤

### 任务 1：锁定三类真实样本与格式保真规则

- [ ] 将已获认可的视频、专栏、动态 `content-new` 作为人工验收样本；测试夹具只保留最小结构和脱敏 URL，不复制私人全文。
- [ ] 为 `content.ops[].attributes.header`、`opus.content.paragraphs[].text.nodes[].word.font_level` 等已出现标记建立显式映射；未出现或未知标记原样保留并记录缺口（Gap）。同一图片在原始正文出现两次时，正文仍可出现两次，但物理文件只存一份。
- [ ] 在 `tests/test_bilibili_collector.py` 写失败测试：普通文字“【这个网站能做什么】”保持普通段落，带标题标记的段落才转 Markdown 标题；分别运行 `PYTHONPATH=.:backend/src backend/.venv/bin/python -m unittest tests.test_bilibili_collector -v`，先见目标失败，再实施最小转换并复跑通过。

### 任务 2：作品正文与封面进入结构化投影

- [ ] 在视频采集阶段把作品 JSON 的 `pic` 作为 `cover_url` 标识并下载；失败记明确媒体缺口，不用远端 URL 冒充本地封面。沿用现有媒体域名白名单、大小上限和最多 5 次重试。
- [ ] 将作品标题、URL、类型、首次采集时间、完整正文块和封面哈希写入可再生封套；`Store._export_vault` 不再把旧归档 `content.md` 的“B 站采集 / trigger / 作品”整段塞入正文。
- [ ] 在 `tests/test_sourcehub_markdown.py` 增加视频断言：单一 H1、`## 简介`、本地封面、`## 附件` 中唯一 MP4；专栏/动态断言 `## 正文`、原位图片及不存在空附件章节。先运行目标测试确认失败，再实现并复跑。

### 任务 3：评论及图片按 ID 和关系合并

- [ ] `record_to_fragment` 提供触发、父、根评论的 ID、正文、图片 URL；用已下载媒体映射关联到所属评论，不再把所有图片追加为作品末尾匿名节点。
- [ ] 按评论 ID 保留不同事件；父评与根评同 ID 时只显示一次；多次 @ 共用父评时，正文只展示一份上级评论并列出每个触发评论。不同 ID 即使文本相同也保留。
- [ ] 在 `tests/test_sourcehub_bili_merge.py` 增加三次 @、相同父评、不同 ID 同文本、评论图片归属测试；先见失败，再实现、复跑。

### 任务 4：存量预演、备份与重渲染

- [ ] 编写 `tools/preview_bilibili_rerender.py`：扫描 B 站插件已有 `record.json`，按作品稳定 ID 排序重建；默认只输出待变条目数、缺口和本地链接检查结果，不写真实 Vault。显式 `--apply` 才先备份目标 `content.md` 与 `envelope.json`，再逐条更新。
- [ ] 预演时对三类样本逐一与 `content-new` 核对；任何源记录缺失、媒体不存在或路径无法解析都保留原条目并报告，不猜造内容。迁移后扫描所有 B 站 `content.md` 的本地媒体链接，结果必须为零断链。
- [ ] 增加最小临时 Vault 测试，验证默认预演不改盘、重复 `--apply` 幂等、QQ 文件未变、失败可用备份恢复。只对本次范围跑 `PYTHONPATH=.:backend/src backend/.venv/bin/python -m unittest tests.test_sourcehub_markdown tests.test_sourcehub_bili_merge tests.test_sourcehub_vault tests.test_bilibili_collector -v`。
