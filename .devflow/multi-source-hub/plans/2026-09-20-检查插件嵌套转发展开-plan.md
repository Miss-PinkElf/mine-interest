# 检查插件嵌套转发展开计划

## 一、问题

- 交接 002 记录的「多层转发内层内容缺失」，在本机切换到 QQ 个人号协议（NapCat + aiocqhttp）后已定位清楚：
  - 推送事件里转发段只有 `{"type":"forward","data":{"id":"<res_id>"}}`，**正文不在事件中**；
  - 需二次调用 OneBot v11 接口 `get_forward_msg` 才能取到内层消息树；
  - 检查插件当前只保存外层事件，从不调用该接口，所以快照里永远看不到内层。
- 2026-09-20 已用 NapCat 实际验证（未提交的快照与本地试验文件）：`get_forward_msg` 可返回内层发送者 QQ/昵称/群名片、时间、消息 ID、群 ID、`text` / `image` 等完整消息段。
- 嵌套转发表现：外层响应中内层 `forward.data` 同时带 `id` 与 **内联 `content`**（content 又是完整消息对象数组）；再按内层 `id` 单独调用会失败（`retcode 1200`）。因此递归必须以**内联 content 优先**。

## 二、目标

让检查插件在收到含 `Forward` 段的消息时，自动调用 `get_forward_msg` 展开完整内层树并落盘，供用户在本地用真实消息实测。

## 三、方案（最小改动）

1. 新增 `forward_expander.py`：负责取 `bot.call_action`、调用 `get_forward_msg`、递归补全嵌套 `content`、统计摘要。
2. 新增 `constants.py`：集中常量（日志前缀、目录名、嵌套深度上限、接口名）。
3. 改造 `main.py`：在原有快照落盘之后，追加转发展开流程；有转发段才触发，无转发段完全走原路径。
4. 落盘位置：`data/sourcehub-inspector/forwards/<UTC时间>_<外层message_id>_<forward_id>.json`；原有 `snapshots/` 行为不变。
5. 日志：仍用 `self.logger`，前缀 `[SourceHub Inspector]`，新增一行展开摘要（层数、消息条数、段类型统计），便于不打开 JSON 也能判断是否成功。
6. `metadata.yaml` 的 `support_platforms` 由 `qq_official` 改为 `aiocqhttp`（当前实际平台），版本号 0.1.0 → 0.2.0。

### 关键决策

| 决策点 | 选择 | 理由 |
| --- | --- | --- |
| 递归数据来源 | 优先内联 `content`，缺失才按 `id` 再请求 | 实测按内层 id 递归会 `retcode 1200` 失败 |
| 是否需要二次接口 | 需要 | 推送事件不含正文，不调用就拿不到内层 |
| 深度上限 | 硬编码常量，暂定 5 层 | 防异常数据无限递归；实测样例最深 3 层 |
| 平台判断 | 无 `call_action` 直接跳过并记日志 | 非 aiocqhttp 平台不应报错或静默失败 |
| 是否改 NapCat 的 `parseMultMsg` | 本轮不改 | 属全局配置，会影响其他插件；插件侧展开已足够 |

## 五、验证方式

1. 覆盖本机 `~/.astrbot/data/plugins/astrbot_plugin_sourcehub_inspector/`，在 WebUI 重载插件。
2. 用户用带唯一内外层文字标记的样例转发：一层纯文本、一层带图、两层嵌套。
3. 通过标准：
   - 日志出现展开摘要，且层数/条数与实际相符；
   - `forwards/` 下 JSON 能读到内层每条的发送者、时间、文本段；
   - 嵌套层的内层消息同样出现，不停留在 `[转发消息]` 文案。
4. 失败标准：只有 `Forward.id`、没有内层 `content`，或日志报 API 失败。

## 五之二、第二轮补充（2026-09-20 18:55 实测后）

首次实测已成功展开 3 层 / 35 条（含 157 张图片、19 段文本），但暴露两个问题：

| 问题现象 | 原因 | 解决方案 |
| --- | --- | --- |
| 展开结果只有原始 OneBot JSON，人读不了 | 只落盘结构化数据，没有可读输出 | 新增 `forward_renderer.py`，与 JSON 同时输出一份 `.txt` 可读转录 |
| 有一条转发展开出 0 条 | 直连 NapCat 复核同一 id 仍返回 `status=ok, retcode=0, messages=[]`，**不是插件问题** | 日志把「0 条」单独降级为警告，避免与正常展开混淆 |
| 参数名回退可能被空结果短路 | `fetch_forward_messages` 拿到空列表就返回，不再尝试下一个参数名 | 改为「拿到非空列表才返回」，全部为空才返回空 |

## 六、本轮不做（Deferred Scope）

- **媒体持久化**：内层图片目前只记录 `file` / `url`，图片临时文件仍会消失。暂不做下载/复制。
  - 原因：本轮先证明「内层树能取到」，媒体落盘是独立缺口。
  - 后续触发条件：本轮展开验证通过后立即处理（见 `bug-log.md` 未解决项）。
- **快照脱敏与事件边界收缩**：仍保存整个 `event`（含 `bot` / `platform`），原始 CQ 码含 `rkey=` 鉴权参数。
  - 后续触发条件：与媒体持久化同批处理。
- **事件身份修复**（`event.message_id` 回退时间）与重复检测：本轮不动。
- **正式收藏桥接**：本轮仍为诊断工具，不合并进播放/收藏链路。
