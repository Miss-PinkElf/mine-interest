# 直连下载重试与历史补救 Implementation Plan

> 执行方式：本会话顺序实施（Inline Execution）；代码提交须按仓库约束另行询问。

**目标（Goal）：** QQ 和 B 站媒体下载默认直连，对可恢复错误最多尝试 5 次，历史 B 站失败图片可安全补救。

**结构（Architecture）：** 保持现有下载客户端不使用环境代理；在网络请求层做有限重试和错误分类。历史补救读取原始记录的失败媒体 URL，仅补缺失文件，保留已成功内容及明确失败原因。

**技术栈（Tech Stack）：** Python、aiohttp、urllib、unittest、AstrBot。

- `backend/src/sourcehub/download.py`：QQ/通用同步媒体直连下载与重试。
- `integrations/astrbot/astrbot_plugin_sourcehub_bilibili/client.py`：B 站异步媒体直连下载、主机校验与重试。
- `integrations/astrbot/astrbot_plugin_sourcehub_bilibili/store.py`：失败媒体补救及已有档案安全回填。
- `integrations/astrbot/astrbot_plugin_sourcehub_bilibili/store.py` 与 `main.py`：可重复执行的启动补救入口。
- `tests/test_sourcehub_download.py`、`tests/test_bilibili_collector.py`：请求次数、失败分类、真实档案形态的合成回归。

## 任务 1：下载重试

- [ ] 添加合成测试：前四次瞬时错误、第五次成功；五次都失败；大小超限和不允许的主机只尝试一次；设置系统代理变量时实际客户端仍直连。运行目标测试，确认新断言先失败。
- [ ] 在两种客户端中使用具名 `MAX_MEDIA_ATTEMPTS = 5`，只重试超时、连接中断、429 和 5xx；对 4xx、体积超限、主机校验失败立即返回。每次请求仍使用禁用环境代理的会话或 `ProxyHandler({})`。
- [ ] 同步通用 `download.py` 到两插件内嵌共享库；运行 `PYTHONPATH=backend/src backend/.venv/bin/python -m unittest tests.test_sourcehub_download tests.test_bilibili_collector -v`，预期全部通过。

## 任务 2：补救历史失败媒体

- [ ] 先检查用户指定专栏在插件原始记录中的媒体错误类别，不把含鉴权参数的 URL 输出到日志或测试文件。
- [ ] 新增补救入口：只扫描失败媒体；下载成功后按现有哈希规则落盘并重新导出 Vault；失败则保留原有内容与可核查的错误类别。测试重复运行、部分成功、原文保留。
- [ ] 在真实资料上先预演待补项，再执行用户指定专栏的补救；核对图片落盘或失败原因，并运行第二次预演确认已成功项不再处理。
