# QQ 收藏群主动收藏提案（Proposal）

用户最新要求暂停实施。本文待审，不因本轮获准提交文档而成为已批准实现；新会话先讨论/审阅，按 `../handoffs/2026-09-09-001-规格待审暂停.md` 恢复。

## 背景

用户将感兴趣的消息、图片、文件和聊天记录主动转发到只有自己几个账号的 QQ 收藏群。目标是保持这个习惯，同时可靠保存原始内容，自动形成可持续维护的知识，并允许外部智能体使用。

现有仓库以文档为主，尚无对应业务应用。已完成框架调查并确认复用 AstrBot；无需重新开发消息平台登录、连接和协议。用户已确认自己是收藏群群主，但真实机器人权限仍未验证。

## 非目标与范围边界

- 不自建多平台 Bot 框架，不安装三个候选框架，不改造 AstrBot 为私有大分支。
- 不把 AstrBot 内置检索增强生成知识库（RAG Knowledge Base）当作本项目唯一知识存储。
- QQ 官方事件源不承诺任意历史回补；专用收藏群既有历史导入另作能力核验。
- 不以本文授权 GitHub 远端创建、推送或上传私人内容。本地 Git 历史包含在首期；远端同步意图保留在 `../backlog.md`，范围确认后写独立同步规格。
- 其他 AstrBot 平台共用桥接设计，启用时验证具体字段；当前完成声明只覆盖经过真实验证的平台。
- 不自研笔记编辑前端；首期通过 CLI 和文本文件编辑临时副本后提交服务，不永久排除后续界面。

## 本轮不做 / 后续阶段

对象为持续从其他日常 QQ 群按规则（Rule）、正则表达式（Regular Expression）及大语言模型（LLM）辅助判断选择收藏。原因是用户明确先完成主动收藏；触发为主动收藏闭环验收后用户启动下一阶段。后续再对齐群范围、规则组合和模型参与，编写新计划及规格。不是永久放弃，不影响首期收藏群接收及自动整理。

真相源：`../deferred/QQ指定群持续收集与规则筛选.md`。

## 边界场景

- 同一 payload 多次投递不重复；不同来源相同正文不得全局误合并。
- 收集者转发产生新消息 ID 且原始来源丢失时，标疑似重复，无法证明相同不得静默丢弃。
- 群回执和机器人消息不能无限循环入库；选定本人账号来源白名单属权限，不是延期的内容筛选引擎。
- API 暂时不可用时，已落桥接缓存的事件恢复后重放；暂停窗口内平台没送达的消息可能缺失。
- 用户编辑过的原文不能被重复采集覆盖；模型提交过时版本要冲突，而不是覆盖新内容。
- 附件下载 URL 过期，保留资料状态与错误并允许重试；未经恢复不可宣称附件齐全。
- 账号无法开启群全量权限时，先报告平台门禁失败，不静默改为私聊或强制 @。
