## 一、问题现象与根因

### 1.1 现象（回执表实证，时间为 UTC，本地 +8）

| 本地时间 | 消息 | 回执状态 | 实际结果 |
| --- | --- | --- | --- |
| 00:23:39 | 你看下上次对话为啥卡住了… | `cancelled` | 被 `/goon` 取消，用户从未收到任何回复 |
| 00:28:40 | hihi | `cancelled` | 排队后被取消，无回复 |
| 00:28:54 | `/goon` | `done` | 实际 00:38:42 才返回，`turns` 139 有 2370 字回复 |
| 00:29:02 | `/end` | `done` | 排在 `/goon` 之后执行 |

用户视角：`/goon` 发出后 10 分钟无任何反馈，期间又发了 `/end`，最终在 00:38 才收到回复。

### 1.2 根因

**根因 A：取消被伪装成本地成功**（`sessions.py:141`）

```python
return await self._execute(...) or ""
```

`_execute` 在 `asyncio.CancelledError` 分支返回 `None`；`or ""` 把 `None` 变成空字符串。随后：

- `service.py:88` 判 `reply is not None` → 回执标 `done`（实际是取消）
- `main.py:256` 判 `if reply:` → 空字符串不发送（用户完全静默）

**根因 B：中断动作没有告知被中断方**

`sessions.goon` 开头 `await self.interrupt(conversation)` 的返回值 `bool` 被直接丢弃。用户无法知道「我这一下 `/goon` 掐掉了什么」。

**根因 C：执行期间零反馈**（`sessions.py::_execute`）

所有 `TEXT` 事件被攒进 `parts` 列表，进程退出后才一次性返回。上一轮 agent 实际执行 15 分钟、调用 Bash 67 次，QQ 侧全程空白。

## 二、改动范围

### 2.1 `sessions.py::goon`

```python
async def goon(self, conversation, settings, prompt, message_id) -> str:
    interrupted = await self.interrupt(conversation)
    async with self._lock(conversation):
        self._ensure_open()
        self.store.mark_message(conversation, message_id, RECEIPT_PROCESSING)
        record = self.store.active(conversation)
        if record is None or not record.agent_session_id:
            return NO_ACTIVE_SESSION_REPLY
        reply = await self._execute(
            record, self._model_for_record(record, settings), prompt, message_id, settings
        )
        if reply is None:
            # 本轮执行本身被后续命令取消；必须给用户明确答复，不能静默。
            return AGENT_INTERRUPTED_REPLY
        return f"{GOON_INTERRUPTED_PREFIX}{reply}" if interrupted else reply
```

要点：

- 去掉 `or ""`，取消不再伪装成空成功。
- `_execute` 返回 `None`（本轮被取消）时回 `AGENT_INTERRUPTED_REPLY`，实现「done ⟺ 真的发出去了」。
- `interrupted` 为真时加前缀，说明这次 `/goon` 中断了上一条执行。
- 返回值类型保持 `str`，`service.handle` 的 `reply is not None` 逻辑不用改。

### 2.2 `commands/registry.py`：新增「会启动代理」判定

新增具名常量与函数，作为「哪些输入会跑代理」的唯一真相源：

```python
ALWAYS_AGENT_COMMANDS = frozenset({"/goon", "/cc"})
ARGUMENT_AGENT_COMMANDS = frozenset({"/new", "/!"})

def will_run_agent(command: tuple[str, str] | None) -> bool:
    if command is None:
        return True
    name, argument = command
    if name in ALWAYS_AGENT_COMMANDS:
        return True
    if name in ARGUMENT_AGENT_COMMANDS:
        return bool(argument)
    return False
```

`/help`、`/info`、`/pwd`、`/cd`、`/end`、`/resume`、`/approve`、`/deny`、`/initbase` 均为同步返回，不发执行回执，避免刷屏。

> **对上一轮口头建议的修正**：我此前说「只对纯文本发回执，命令都同步返回」是错的 —— `/goon`、`/cc` 同样会跑代理，恰恰是最需要回执的场景。此处按「是否会启动代理」判定。

### 2.3 `service.py::handle`：执行前回调

```python
async def handle(self, message, decision, claimed=False, on_started=None) -> str | None:
    if self.sessions.is_closing:
        return None
    if not claimed and not self.store.claim_message(message):
        return None
    settings = decision.settings
    assert settings is not None
    command = parse_command(message.text)
    if on_started is not None and will_run_agent(command):
        await on_started()
    ...
```

- 回执在 `claim_message` 之后发，重复消息不会误回执。
- service 不持有 AstrBot context，通过回调注入，保持分层。

### 2.4 `main.py`：注入回调

```python
reply = await self.service.handle(
    message, decision, on_started=lambda: self._notify_started(message)
)

async def _notify_started(self, message) -> None:
    await send_text(self.context, message.origin, EXECUTION_STARTED_REPLY, self.logger)
```

- 仅接在前台 `on_qq_message` 路径；`_replay_queued`（重启恢复）不接，避免启动时批量刷屏。
- 回执发送失败不阻断主流程（`send_text` 自带兜底，返回 `bool` 被忽略）。

### 2.5 `constants.py`：新增文案常量

- `EXECUTION_STARTED_REPLY`：执行开始回执
- `GOON_INTERRUPTED_PREFIX`：`/goon` 中断前缀

## 五、本轮不做（Deferred Scope）

- **流式输出（Streaming）**：`_execute` 仍攒齐后一次性返回。改为边收边发需要重构 `main.py` 的回复链路与 `send_text` 分段策略，改动面大、与 AstrBot 消息链耦合深。触发条件：真机验证后仍认为「回执不足以消除等待焦虑」，或单轮经常超过 5 分钟。
- **`/goon` 中断排队消息的语义调整**：`/goon` 中断其他排队消息属于其「中断当前执行」的固有语义，本轮不改；若后续需要「只中断当前、保留队列」，属需求变更，需重新对齐。
- **6198 重连日志**：属配置层，不在本计划代码范围内，单独处理（见 `state.md`）。
- **群 701292201**：e2e 专用测试群，本轮不加进生产配置。
- **关键路径正则误伤只读命令**（`permissions.py:141` 对 `/System`、`/Library` 一律 deny，连 `ls` 也拦）：上一轮诊断已记录，本轮不改；触发条件为用户再次在 QQ 内触发画图／字体类任务。

## 六、风险

- 执行回执会让「秒完成的请求」多一条消息。判定为可接受：不触发的命令已排除，纯文本请求本身耗时不可预测。
- `/goon` 被取消时同时回 `AGENT_INTERRUPTED_REPLY`，若取消方（如 `/!`）也回同样文案，`_recent_outgoing` 的 10 秒去重会抑制第二条，不会重复刷屏。
