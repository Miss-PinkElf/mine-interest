## 背景

- 插件默认 `claude_setting_sources=""`，实测会导致 `~/.claude.json` 中的用户级 MCP server 不加载，deepseek-web 工具直接不可见。
- 改成 `user` 后 MCP 能加载，但非交互 `--print` 模式下 MCP 工具需要显式 allow，否则调用被拒。
- 实测权限规则粒度：精确工具名 `mcp__deepseek-web__deepseek_search` 与服务器级 `mcp__deepseek-web` 均可授权，`mcp__*` 通配不生效。
- 实测 deny 会把工具从工具列表移除，PreToolUse hook 的 allow 不会绕过 deny。

## 目标

1. workspace/full 档可用 `mcp__deepseek-web`（服务端搜索 + 服务端抓取）。
2. 所有档位禁用原生 `WebSearch`、`WebFetch`。
3. 所有档位禁用本机 `mcp__fetch`（本地进程直连 URL，有内网访问风险）。
4. 只读档（readonly）新增开关 `readonly_mcp_enabled`，默认开：开启时放行 `mcp__deepseek-web`，关闭时一并禁用。

## 方案

- 常量集中到 `constants.py`：
  - `READONLY_MCP_ENABLED_KEY`、`DEFAULT_READONLY_MCP_ENABLED`
  - `MCP_DEEPSEEK_SERVER_RULE = "mcp__deepseek-web"`
  - `MCP_LOCAL_FETCH_SERVER_RULE = "mcp__fetch"`
  - `DENIED_NATIVE_WEB_TOOL_RULES = ("WebSearch", "WebFetch")`
- `agents/profiles.py` 的 `build_claude_settings` / `ensure_claude_settings` 增加 `readonly_mcp_enabled` 参数：
  - `permissions.deny`：关键路径规则 + 原生联网工具 + 本机 fetch；只读档开关关闭时再加 deepseek-web
  - `permissions.allow`：只读档开关开启时、workspace/full 档，加入 deepseek-web
- `sessions.py` 从配置读取开关并传入 settings 生成。
- `_conf_schema.json` 新增「③ 只读档 MCP 开关」并更新 `claude_setting_sources` 提示（MCP 与鉴权都要求 `user`）。
- README、spec/tasks、版本号同步到 `0.2.2`。

## 验证

1. 单元测试覆盖三档 × 开关的 allow/deny 组合，全部通过。
2. CLI 实测（干净参数模拟插件）：
   - workspace + deny 原生工具：`WebSearch` 返回工具不存在。
   - workspace + allow deepseek：`deepseek_search` 返回结果。
   - readonly 开关开：deepseek 可用；开关关：deepseek 不可用。
   - `mcp__fetch` 在所有档位不可用。
3. 安装目录同步后重载，QQ 侧验证一次群内搜索问答。

## 风险

- `claude_setting_sources` 仍需设为 `user` 才能加载 MCP 与鉴权；本计划不改默认值，只在配置提示中说明。
- 用户级 settings 会随之加载（模型映射、statusLine 等），不影响插件策略文件的 deny/allow。
- 服务端抓取（deepseek_fetch）仍可被群成员用来抓取公开网页内容，只读档的开关默认开是该需求的明确选择。
