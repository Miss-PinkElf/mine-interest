## 现状与目标

- 现状：插件只有一个 `default_model`，`policy.py` 对 Claude Code 和 Codex 都读取它，容易把一方模型名传给另一方 CLI。
- 目标：AstrBot 配置页分别提供“Claude Code 默认模型”和“Codex 默认模型”；所用代理决定读取哪个字段。

## 候选方案与选择

1. **独立字段，停止共享字段（已选择）**：增加 `default_claude_model`、`default_codex_model`；停止读取旧 `default_model`，防止跨代理串用。旧值需由管理员按代理分别填入新字段。
2. **独立字段，保留共享后备值（未选择）**：旧配置可继续生效，但独立字段留空时仍可能把 Claude 模型名传给 Codex。
3. **代理配置 JSON（未选择）**：把两个模型放入嵌套 JSON，字段少但 AstrBot 表单不便直接填写。

## 已确认规则

- 群规则 `group_rules_json.<群号>.model` 非空时覆盖该群所选代理的默认模型。
- 没有群规则模型时，Claude Code 使用 `default_claude_model`，Codex 使用 `default_codex_model`。
- 对应默认模型留空时不传 `--model`，由该代理 CLI 使用自己的默认模型。
- 私聊按 `default_agent` 选择代理，再读取该代理的默认模型。
- 已有会话继续使用持久化的代理类型。若配置中的代理类型后来改变，旧会话应读取原代理的独立默认模型，避免把新代理的模型传给旧会话；需要切换代理时用 `/new` 建立新会话。
- 旧 `default_model` 停止生效并从配置表单移除；管理员自行在 AstrBot 填写新字段。

## 本轮不做 / 后续阶段（Deferred Scope）

- 模型列表查询、聊天中切换模型的 `/model` 命令：本轮仅解决两个 CLI 的静态默认值；命令交互和模型发现依赖阶段 2 的管理能力，第一阶段双代理运行验收后进入阶段 2。该能力没有被永久放弃。
