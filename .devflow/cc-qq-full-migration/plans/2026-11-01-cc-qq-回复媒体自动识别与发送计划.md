## 一、问题与根因

### 1.1 现象

- 代理（Claude，工作目录 `/Users/mobius/Documents/111AAA-code/绘赢喵`）已生成图片 `rc-20261101-011250.png`（5,249,890 字节，2048×2048）。
- 用户说“把图片发给我”后，代理只回复纯文本（374 字），其中包含本地路径与 ossforai 链接，并声称“图片已在上方展示”。
- QQ 群里实际只收到一条图片消息，内容是这段文字的**长文本截图**，不是生成的图。

### 1.2 根因

1. **主因**：图片输出协议 `[[image:<path>]]` 只存在于插件 README 与解析代码，**没有进入代理运行时上下文**；代理不知道要通过标记输出图片，因此从不使用。生产库 `cc_qq.sqlite3` 共 196 个回合，含 `[[image:` 的回复为 0 条。
2. **次因**：插件没有兜底，回复中的本地图片路径、图片 URL 不会被识别和发送。
3. **放大因素**：374 字 > `long_text_image_threshold: 360`，整段文本被渲染成长图截图，造成“发出了图片但发错了内容”的观感。

### 1.3 已确认决策（2026-11-01 对话）

| 决策点 | 结论 |
|---|---|
| 本地文件信任范围 | 仅 `work_dir` 与插件媒体目录 |
| URL 处理 | 直接交给 AstrBot 发 URL，本地优先去重 |
| 视频 | 本轮一起做，真机验证 |
| 总开关 | 新增 `auto_send_media`，默认开 |

## 二、目标与非目标

### 2.1 目标

1. 代理回复中出现可信的本地图片/视频路径时，插件自动按原位置发送。
2. 回复中出现图片/视频 URL 时，插件自动发送 URL（本地优先去重）。
3. 自动识别存在媒体时，不再把整段回复渲染成长图。
4. 通过 `auto_send_media` 开关可一键关闭，回到现有行为。
5. 安全边界不弱于现有 `[[image:]]`：本地文件不得越出 `work_dir` / 插件媒体目录。

### 2.2 非目标（本轮不做）

- 不强制给代理注入协议提示（方案 A/B 另议）。
- 不做大图压缩、转码、缩略图。
- 不做 URL 预下载与防盗链处理。
- 不做文件（非图片/视频）发送。
- 不改动输入侧媒体能力。

## 三、详细设计

### 3.1 识别规则

#### 本地路径（图片/视频）

- 形态：
  - 绝对路径：`/Users/...`；
  - 用户目录：`~/...`；
  - 显式相对路径：`./...`、`../...`；
  - Markdown 图片：`![alt](/path/a.png)`；
  - 行内反引号包裹：`` `/path/a.png` ``（**必须支持**，本次现场就是这种形态）。
- 解析：
  - 相对路径按当前 `work_dir` 解析（复用 `resolve_trusted_path` 的行为）；
  - 必须真实存在；
  - 必须位于 `work_dir` 或插件媒体目录（复用 `media.py::resolve_trusted_path`）。
- 校验：
  - 图片：复用 `media.py::validate_image`（PIL 实检验证 + `MAX_IMAGE_BYTES = 10 MiB`）；
  - 视频：扩展名白名单 `.mp4` / `.mov` / `.webm` + `MAX_VIDEO_BYTES`（建议 100 MiB）+ 文件存在。
- 非媒体形态不做处理：`[[image:]]` 之外的裸文件名（如 `a.png` 不带路径前缀）不自动识别，避免误判正文。

#### URL（图片/视频）

- 仅识别 `http://` / `https://`，且路径以媒体扩展名结尾（允许 query），例如：
  - `https://.../xxx.png`
  - `https://.../xxx.mp4?token=...`
- 发送方式：`Image.fromURL` / `Video.fromURL` 交给 AstrBot → NapCat 抓取，插件不下载。
- 失败只告警，不影响其余文本与媒体。
- 安全：
  - 拒绝 `localhost`、回环地址、私网地址（`10/8`、`172.16/12`、`192.168/16`、`127/8`、IPv6 回环），防 SSRF；
  - 只允许 http/https，拒绝 `file://` 等 scheme。

### 3.2 顺序、去重与上限

- 显式 `[[image:<path>]]` 标记优先解析，自动识别只处理剩余文本段，避免重复。
- 按在回复中出现的顺序与文本混排。
- 单条回复最多 `AUTO_MEDIA_MAX_COUNT = 10` 个媒体；超出的丢弃并告警。
- 去重：
  - 本地路径按 `realpath` 去重；
  - URL 按规范化字符串去重；
  - **本地优先**：同一条回复中若已识别到可信本地图片/视频，则丢弃该回复中的 URL 媒体，避免同一张图发两遍（本次场景同时出现本地路径与 URL）。

### 3.3 文本清理

- 命中的路径/URL 从文本中移除，并清理 Markdown 图片语法 `![alt](path)`。
- 命中行若因此变空，则删除该行；其余文本保持原样。
- 不做额外提示（不向群里发“已自动发送 N 个附件”）。

### 3.4 与长文本长图的关系（关键）

现有：`render.py::should_render_image()` 在文本含 `[[image:` 时不转长图。

调整为：

1. `main.py::_deliver()` 先做回复解析：显式标记 + 自动识别；
2. 若解析结果含图片/视频，直接按图文发送，**不进入长图分支**；
3. 若不含媒体，保持现有长图逻辑不变。

这样本次 374 字回复会发送文本 + 生成的图片，而不是整段文字长图。

### 3.5 开关

- 新增配置 `auto_send_media`（bool，默认 `true`）。
- 关闭后行为完全回到 `0.3.2`：只认 `[[image:<path>]]`。
- 配置读取沿用 `main.py::_config_flag()`，`null` 视为默认值（历史 B1 缺陷教训）。

### 3.6 安全边界

- 本地文件绝不越出 `work_dir` / 插件媒体目录；
- 图片必须通过 PIL 实检；
- 视频仅扩展名 + 大小校验（NapCat/QQ 侧失败只告警）；
- URL 私网拦截；
- 单条数量上限 10；
- 识别与发送全程不执行外部命令。

## 六、风险与回滚

| 风险 | 处理 |
|---|---|
| 误发正文里的示例路径 | 只认带路径前缀或 Markdown/反引号形态；跳过围栏代码块 |
| 同一张图重复发送 | 本地优先去重 |
| 视频在 NapCat 侧失败 | 单媒体失败只告警，不影响文本；记录真机结论 |
| 私网 URL / SSRF | 私网地址与回环拦截 |
| 长回复不再长图 | 这是预期行为：有媒体时优先媒体；无媒体仍走长图 |
| 回滚 | `auto_send_media=false` 即回到旧行为；必要时回退代码 |

## 八、本轮不做 / 后续阶段（Deferred Scope）

- **代理协议提示（方案 A/B）**：本轮用自动识别兜底，不注入系统提示，也不改 `initbase` 模板。触发条件：自动识别仍频繁漏发，或希望代理主动使用显式标记。
- **大图压缩**：本次 5.0 MB 在 10 MiB 限制内，可直接发送；若实际出现 QQ 压缩严重或发送失败，再评估压缩策略。
- **URL 预下载**：本轮直接发 URL；若出现链接过期或防盗链失败，再改为下载到插件媒体目录。
- **文件发送（非图片/视频）**：本轮不做。
- **视频扩展名与大小可配置**：先固定常量；出现实际需求再配置化。
