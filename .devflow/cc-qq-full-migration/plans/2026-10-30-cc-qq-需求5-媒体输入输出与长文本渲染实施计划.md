## 三、阶段 A：媒体输入（G2）

### A1. 常量与配置

**`constants.py` 新增**

- `MAX_INCOMING_IMAGES = 6`：单条消息最多图片数
- `MAX_IMAGE_BYTES = 10 * 1024 * 1024`：单张图片上限
- `MEDIA_RETENTION_DAYS = 7`：媒体保留天数
- `MAX_FORWARD_MESSAGES = 30`：合并转发最多展开条数
- `MAX_FORWARD_CHARS = 8000`：合并转发文本总字符上限
- `AGENT_ENV_MEDIA_ROOT = "CC_QQ_MEDIA_ROOT"`：注入 hook 的媒体根环境变量
- 文案常量：图片数量超限、转发过大、图片下载失败、档位不支持等

**`_conf_schema.json` 新增**

- `media_enabled`（bool，默认 true）
- `max_incoming_images`（int，默认 6）

### A2. 数据契约（`contracts.py`）

`IncomingMessage` 增加（保持 `frozen=True`，用 `dataclasses.replace` 更新）：

- `images: tuple[str, ...] = ()`：直接图片的原始引用（URL／file）
- `quoted_text: str = ""`
- `quoted_images: tuple[str, ...] = ()`
- `forward_text: str = ""`
- `forward_images: tuple[str, ...] = ()`

`AgentRequest` 增加：

- `images: tuple[str, ...] = ()`：已落盘的本地绝对路径

### A3. 事件解析（`platform/qq_events.py`）

- `SUPPORTED_TEXT_SEGMENTS` 扩展为 `{"Plain", "At", "Image", "Reply", "Forward"}`；`Record`／`Video`／`File` 等仍标记不支持。
- 直接图片：取 `Image.url` → `Image.file` → `Image.path` 中第一个非空值。
- 引用消息：读取 `Reply.chain`，提取其中的 `Plain` 文本与 `Image` 引用；`chain` 为空时用 `Reply.message_str` 兜底。
- 合并转发：`Forward` 段只携带 `id`，本层**只记录 id**，展开放到 A4 的异步步骤（保持 `parse_qq_event` 同步纯函数）。
- 新增 `has_media` 判定：只有媒体、无文本的消息不再回复 `EMPTY_MESSAGE_REPLY`。

### A4. 媒体落盘（新增 `media.py`）

职责：

1. `materialize(event, message, media_root) -> IncomingMessage`
   - 解析 `Forward.id`：`OneBotClient(event).get_forward_msg(id)` → `OneBotPayloadParser.parse_get_forward_payload(payload)`，提取文本与图片；受 `MAX_FORWARD_MESSAGES`／`MAX_FORWARD_CHARS` 限制。
   - 下载直接图片与转发／引用图片：调用 `Image.convert_to_file_path()`。
   - 落盘路径：`<media_root>/<会话键哈希>/<YYYYMMDD>/<message_id>/<序号>.<ext>`。
   - 类型校验：扩展名白名单（jpg/jpeg/png/gif/webp/bmp）；大小 ≤ `MAX_IMAGE_BYTES`；数量 ≤ `MAX_INCOMING_IMAGES`。
   - 单张失败不影响其它图片；失败计入日志与提示。
2. `cleanup(media_root, now)`：删除超过 `MEDIA_RETENTION_DAYS` 的目录；在 `initialize()` 中调用一次。
3. `is_trusted_path(path, work_dir, media_root)`：`realpath` 后必须位于两者之一。

**待实现时确认**：`event.bot.api.call_action` 在 aiocqhttp 适配器下是否可用；不可用时退回 `event.message_obj.raw_message` 原始段与 `get_msg`。

### A5. 只读档媒体根放行（M1）

- `permissions.classify_tool_call(tool_name, tool_input, profile, work_dir, extra_read_roots=())`：
  - `PROFILE_READONLY` 且 `tool_name in READ_TOOLS`：目标路径在 `work_dir` **或任一** `extra_read_roots` 内即放行。
  - `PROTECTED_READ_ROOTS` 与硬拒绝规则仍然优先。
  - 写工具与 `Bash` 仍然一律拒绝。
- `hooks/readonly_hook.py`：读取 `AGENT_ENV_MEDIA_ROOT`，传入 `extra_read_roots`。
- `sessions._execute`：把 `media_root` 注入 `process_env`（所有档位都注入，只有只读档使用）。

### A6. 传给代理

- `SessionManager.run/new/goon` 增加 `images` 参数，透传到 `_execute` → `AgentRequest.images`。
- `_execute` 组装 prompt：
  ```
  <用户原文>

  [用户发送的图片]
  1. /abs/path/1.jpg
  2. /abs/path/2.jpg

  [被引用的消息]
  <quoted_text>

  [被引用的图片]
  1. /abs/path/q1.jpg

  [转发的消息]
  <forward_text>
  ```
  无内容的段落整段省略。
- 纯图片无文本时，prompt 正文写一句固定提示（如"用户只发送了图片，请查看后回应"）。
- Claude：仅靠 prompt 路径 + 提示"可用 Read 工具查看图片"。
- Codex：`codex_args(..., images=request.images)` 追加 `-i <path>`；**实现时先用 `codex exec --help` 与 `codex exec resume --help` 确认 `resume` 是否支持 `-i`**，不支持则仅在首轮传图并在 prompt 中说明。

### A7. 主链路（`main.py`）

- 在 `parse_qq_event` 之后、`authorize` 之前调用 `media.materialize`（需要 event）。
- 媒体处理失败时回复明确文案，不静默。
- `has_unsupported_segments` 的判定改为"存在 Record／Video／File 等仍未支持的段"。

## 四、阶段 B：发送图片（G3）

### B1. 标记协议（P1）

- 语法：`[[image:<path>]]`，可出现在回复任意位置，可多个。
- 常量：`IMAGE_MARKER_PATTERN`（正则）、`IMAGE_MARKER_MAX_COUNT = 10`。

### B2. 发送实现（`platform/replies.py`）

- 新增 `send_reply(context, origin, content, logger, work_dir, media_root)`：
  1. 按正则切分为文本段与图片段。
  2. 每个图片路径做 `is_trusted_path` 校验；不可信路径剔除并记录日志，不阻断文本发送。
  3. 用 `MessageChain([Plain(...), Image.fromFileSystem(...)])` 按原顺序发送；文本段超过 `MAX_QQ_TEXT_CHARS` 继续分段。
  4. 单条消息最多 `IMAGE_MARKER_MAX_COUNT` 张图。
- 现有 `send_text` 保留，内部委托给 `send_reply`（无标记时行为不变），避免大范围改调用点。

### B3. 调用点

- `main._send_reply`、`_replay_queued`、`_notify_interrupted`、`_notify_started` 全部改为 `send_reply`，并传入当前会话的 `work_dir` 与 `media_root`。
- 审批通知（`_notify_approval`）不传图片上下文，仍走纯文本。

## 五、阶段 C：长文本渲染长图（G4）

### C1. 渲染封装（新增 `render.py`）

- `should_render_image(text, enabled, threshold) -> bool`：
  - `enabled` 为假 → false；
  - `len(text) >= threshold` → true；
  - 含围栏代码块（行首 ```）→ true。
- `render_markdown_image(text) -> Path`：
  - 在线程中执行 `asyncio.run(HtmlRenderer().render_t2i(text, use_network=False))`，避免阻塞主事件循环。
  - 网络渲染作为可选配置（默认关）。
- `split_long_image(path, max_height) -> list[Path]`：高度超过 `MAX_T2I_IMAGE_HEIGHT`（默认 4000px）时用 Pillow 垂直切分。
- 失败语义：捕获异常，返回空列表，由调用方回退文本。

### C2. 发送链路

- `main._send_reply` 在拿到最终回复后：
  1. 查询会话 `/img` 开关与全局配置；
  2. 命中触发条件 → 渲染长图 → 逐张发送 `Image`，**不再发全文文本**；
  3. 渲染或发送失败 → 回退 `send_reply` 文本分段；
  4. 未命中 → 正常 `send_reply`。
- 长图发送同样受 10 秒重复回复抑制与最小间隔约束。

### C3. `/img on|off`

- `commands/registry.py`：`Command("/img", "/img on|off", "开关本会话长文本转图片", ROLE_ADMIN)`。
- `commands/session.py`：开关结果文案。
- `service._command`：读写会话开关；无参数时返回当前状态与用法。
- `storage.py`：新增 `conversation_flags(conversation_key TEXT PRIMARY KEY, flags_json TEXT)` 表与 `get_flag`／`set_flag`。
- `/img` 不启动代理，`will_run_agent` 自然返回 false，无需改判定。

### C4. 配置项

- `long_text_image_enabled`（bool，默认 true）
- `long_text_image_threshold`（int，默认 **360**）
- `long_text_image_use_network`（bool，默认 false）
- `long_text_image_max_height`（int，默认 4000）

### 7.2 真机验收（测试实例 `~/.astrbot-e2e`，群 `701292201`）

8. 回复含 ```diff 代码块 → 收到长图。

10. 回归：`/help`、`/pwd`、`/cd`、`/cc`、`/goon`、`/!`、审批流程不受影响。

## 八、风险与回滚

| 风险 | 缓解 |
| --- | --- |
| 只读放行媒体根扩大读取面 | 只放行插件媒体目录；`realpath` 校验；写工具仍拒绝；补单测 |
| 外网图片下载慢／大 | 超时、大小、数量三重限制；失败不阻断其它图片 |
| 转发展开撑爆上下文 | 条数与字符双上限，超出截断并提示 |
| T2I 渲染阻塞事件循环 | 线程中执行；失败回退文本 |
| Codex `-i` 在 `resume` 下不可用 | 实现时先验证；不支持则首轮传图 |
| QQ 发图频繁触发风控 | 复用 10 秒重复抑制；长图每次回复最多一组 |

**回滚**：所有改动集中在插件目录内，按文件粒度回滚；版本号回退到 `0.2.5`；媒体目录可直接删除；不涉及数据库结构破坏（新增表用 `CREATE TABLE IF NOT EXISTS`）。
