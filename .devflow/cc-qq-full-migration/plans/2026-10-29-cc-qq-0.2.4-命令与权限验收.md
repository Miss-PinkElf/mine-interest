## 本轮范围（Scope）

**只做 A+B**：

- A：同步命令（不启动代理、秒级返回）。
- B：owner / admin / member / guest 三级角色权限（含 `/cd` 序号切换与 `/initbase`）。

**本轮不做（Deferred Scope）**：

- C：真实代理执行（普通消息、`/cc`、`/goon`、执行中 `/!`、deepseek 搜索、危险操作审批）。原因：单轮可能数分钟、消耗 token，且依赖 `claude_setting_sources=user`；待用户确认后单独排期。
- 富媒体（图片/文件）与私聊链路。原因：首版 E2E 只支持文本；私聊需额外测试账号与配置。

## 配置改动协议

所有改动只发生在测试实例，测完恢复：

1. 备份到 `~/.astrbot-e2e/backups/cc_qq_config-<时间戳>.json`；
2. 修改 JSON 后通过 WebUI `/api/v1/plugins/reload` 重载插件；
3. 用 `/pwd` 的输出（角色/权限档）确认新配置已生效；
4. 若 reload 不生效，回退方案：`stop-instance` → 改配置 → 以 `ASTRBOT_ROOT=~/.astrbot-e2e astrbot run` 手动启动并写 pid 文件；
5. 测试结束恢复备份并重载，再次用 `/pwd` 确认回到 owner/full。

## 执行方式

- 复用 `tools/astrbot_e2e/onebot.py` 的 `OneBotClient` 与消息构造，写一个**临时驱动脚本**（放 `/tmp`，不入库）：
  - 连接 `6200`（机器人）与 `6201`（发送者）；
  - 逐条发送、等待首条回复（默认 8 秒），并收集 1 秒内连续回复；
  - 「无回复」用例等待 3 秒；
  - 记录原始回复到 `/tmp/ccqq-accept-<时间戳>.json`。
- 每条用例判定「通过 / 失败 / 跳过」，失败时保留原始回复。
- 重复文案的用例之间强制间隔 ≥11 秒（`PRIVATE_DUPLICATE_WINDOW_SECONDS = 10` 的重复回复抑制）。
- 结束后：
  1. 恢复配置并 reload，跑 R1/R2；
  2. 停止测试实例？**不停止**，保留给后续 C 阶段；若用户要求再停。
  3. 把结果写入验收报告文档，并回填 `state.md` / `checkpoints.md` / `spec/feature-mapping.md` 的证据。

## 风险与回滚

| 风险 | 处理 |
| --- | --- |
| reload 不重新读取配置文件 | 回退为手动重启测试实例（见「配置改动协议」第 4 步） |
| 相同文案被 10 秒重复抑制吞掉 | 用例间强制 ≥11 秒间隔 |
| 改坏测试配置 | 每阶段前备份；结束后恢复并 `/pwd` 校验 |
| `/initbase` 写入文件 | 只写 `~/.astrbot-e2e/workdir`，不碰仓库 |
| 生产影响 | 无：只操作 `~/.astrbot-e2e` 与测试群；生产 AstrBot `6199` 与生产群不动 |
