## 问题定位

- 问题现象（Symptom）：AstrBot 显示“压缩包不是合法的 AstrBot 插件：未找到 metadata.yaml 或 metadata.yml”。
- 问题原因（Root Cause）：用户上传的 `integrations/astrbot/astrbot_plugin_cc_qq.zip` 同时含 `astrbot_plugin_cc_qq/` 和 macOS 资源目录 `__MACOSX/`。本机 AstrBot 的 `_resolve_archive_root_dir()` 对两套顶层目录求公共根，得到 ZIP 根层；随后只在该层查找 `metadata.yaml`，因此忽略嵌套在插件目录内的元数据文件。
- 解决方案（Fix）：从插件源码目录生成不含 `__MACOSX`、AppleDouble、缓存和字节码的 ZIP，使 `metadata.yaml` 位于 ZIP 根层；保留 Python 包相对路径。

## 实施与核对

1. 只生成新的上传压缩包，保留用户原 ZIP 供问题追溯；不修改插件 Python 代码或版本。
2. 列出 ZIP 条目，确认根层有 `metadata.yaml`、`main.py`、`_conf_schema.json`，且不存在 `__MACOSX/`。
3. 使用本机 AstrBot 的归档检查接口（Archive Inspector）核对结构和元数据；只做离线校验，不代替在 UI 中安装与真实 QQ 验收。
4. 更新 README 与 mission 状态，交付可上传的 ZIP 路径，由用户自行上传安装。

## 修复结果与证据

- 交付文件：`integrations/astrbot/astrbot_plugin_cc_qq-upload.zip`，约 23 KB；旧 `integrations/astrbot/astrbot_plugin_cc_qq.zip` 保留作故障样本。
- `unzip -Z1` 显示 `metadata.yaml`、`main.py`、`_conf_schema.json` 均在 ZIP 根层，且没有 `__MACOSX/`。
- `unzip -tq` 报告压缩数据无错误；本机 AstrBot `_PluginUpdater.validate_plugin_archive()` 返回 `metadata.yaml`。
- 用户于 16:23 上传新 ZIP；本机 AstrBot 日志显示 `Installed plugin astrbot_plugin_cc_qq-upload.zip successfully`，并加载 `astrbot_plugin_cc_qq (0.1.12)`。安装故障已解决，QQ 对话仍待独立验收。
