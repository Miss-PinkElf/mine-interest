## 本轮建议的产品决定

实施时按下面三条做。若要改，先改本计划再写代码。

- 群聊里 @ 了机器人但没有文字，仍回复 `EMPTY_MESSAGE_REPLY`。只有私聊空文本改为不回复。
- 过期秒数放进 AstrBot 插件设置，键名 `stale_message_max_age_seconds`，类型整数，默认 `180`。代码里的 `DEFAULT_STALE_MESSAGE_MAX_AGE_SECONDS` 只作为缺省和非法值的回落。事件时间晚于收到时刻（时钟偏差）时当作新消息。原始 `time` 缺失时不丢弃。填 `0` 表示关闭按时间忽略，断网补来的消息仍会回复。负数、布尔值或非整数回落到 180。
- 插件启动时重放的 `queued` 回执不套过期过滤。那些是断线前已经领走、还没跑完的消息，不是 QQ 事后补推的历史。

```python
def onebot_event_time(event) -> int | None:
    """只读 OneBot 原始 time。AstrBot 的 message_obj.timestamp 是收到时刻，不能用来判断过期。"""
    message_obj = getattr(event, "message_obj", None)
    raw = getattr(message_obj, "raw_message", None)
    if not isinstance(raw, dict):
        return None
    value = raw.get("time")
    if isinstance(value, bool) or not isinstance(value, (int, float)) or value <= 0:
        return None
    return int(value)


def stale_max_age_from_config(config: dict) -> int:
    raw = config.get(STALE_MESSAGE_MAX_AGE_SECONDS_KEY, DEFAULT_STALE_MESSAGE_MAX_AGE_SECONDS)
    if isinstance(raw, bool) or not isinstance(raw, int) or raw < 0:
        return DEFAULT_STALE_MESSAGE_MAX_AGE_SECONDS
    return raw


def should_ignore_as_stale(event_time: int | None, now: int, max_age_seconds: int) -> bool:
    if max_age_seconds == 0 or event_time is None:
        return False
    if event_time > ONEBOT_MILLISECOND_TIMESTAMP_THRESHOLD:
        event_time //= 1000
    age = now - event_time
    if age < 0:
        return False
    return age > max_age_seconds


def empty_text_reply(kind: ConversationKind) -> str | None:
    if kind is ConversationKind.PRIVATE:
        return None
    return EMPTY_MESSAGE_REPLY
```

"""代理标准输入被对端关闭时必须变成代理错误。"""

import unittest

from astrbot_plugin_cc_qq.agents.process import AgentProcessError, deliver_prompt


class _Stdin:
    def write(self, data):
        return len(data)

    async def drain(self):
        raise ConnectionResetError("Connection lost")

    def close(self):
        raise AssertionError("drain 失败后不应再 close")


class _Process:
    def __init__(self, returncode):
        self.returncode = returncode
        self.wait_calls = 0

    async def wait(self):
        self.wait_calls += 1
        self.returncode = 3


class DeliverPromptTest(unittest.IsolatedAsyncioTestCase):
    async def test_connection_reset_becomes_agent_process_error(self):
        process = _Process(returncode=None)
        with self.assertRaises(AgentProcessError) as caught:
            await deliver_prompt(_Stdin(), "hi", process)
        self.assertEqual(str(caught.exception), "代理进程在接收消息前退出，退出码 3")
        self.assertEqual(process.wait_calls, 1)

    async def test_known_return_code_skips_wait(self):
        process = _Process(returncode=1)
        with self.assertRaises(AgentProcessError) as caught:
            await deliver_prompt(_Stdin(), "hi", process)
        self.assertIn("退出码 1", str(caught.exception))
        self.assertEqual(process.wait_calls, 0)

```python
async def deliver_prompt(stdin, prompt: str, process) -> None:
    """把用户文本写入标准输入。对端已关闭时转成代理错误。"""
    try:
        stdin.write((prompt + "\n").encode("utf-8"))
        await stdin.drain()
        stdin.close()
    except (BrokenPipeError, ConnectionResetError, ConnectionAbortedError) as exc:
        code = process.returncode
        if code is None:
            with suppress(asyncio.TimeoutError):
                await asyncio.wait_for(
                    process.wait(), timeout=PROCESS_TERMINATE_GRACE_SECONDS
                )
            code = process.returncode
        shown = "未知" if code is None else str(code)
        raise AgentProcessError(f"代理进程在接收消息前退出，退出码 {shown}") from exc
```

## 验收标准（Acceptance Criteria）

- 单元测试覆盖：私聊空文本返回 `None`，群聊空文本仍是原提示；默认 180 秒以外为过期，传入 30 秒时按 30 秒判断，传入 0 时不丢弃；5 秒以内、未来时间和缺失时间都不过期；配置缺失、负数回落到 180，合法整数按配置；毫秒时间戳会先换成秒。
- `ConnectionResetError` 不再冒出 `main.py`。回复文案是“代理进程在接收消息前退出，退出码 N”。退出码尚未出现时先等进程结束，最多等 `PROCESS_TERMINATE_GRACE_SECONDS`。
- 过期消息与私聊空文本不调用 `ConversationService.handle`。图片等非文本段仍回复“当前阶段只支持文本消息”。
- `0.1.14` 的版本常量、元数据和 ZIP 一致。旧 `0.1.13` ZIP 仍在。
- 真实 QQ 上的三条行为要等用户上传后才算验收：断网恢复不再补答旧消息、同一机器人号双端在线时不再刷“请在 @ 后输入”、代理早退时 QQ 能看到退出码。

## 风险

- 过滤看的是 `message_obj.raw_message["time"]`。AstrBot 适配器会把 `message_obj.timestamp` 写成收到时刻，不能拿来判断。若 NapCat 补推时把原始 `time` 也改成当前时间，配置里的秒数不会生效；那时需要再抓一条原始事件，本计划不预先加第二套猜测。
- `stop_event()` 仍会让 AstrBot 发送阶段打出一条正文为空的 `Prepare to send`。发送阶段在消息链为空时会跳过实际发送。本计划不改 AstrBot 核心。
