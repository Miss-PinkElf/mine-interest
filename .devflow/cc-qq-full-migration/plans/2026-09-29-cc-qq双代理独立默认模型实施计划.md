## 目标与边界

- 目标：两个代理各自有默认模型，群规则模型覆盖优先，空值交给 CLI；旧共享 `default_model` 不再影响任一代理。
- 范围：`constants.py`、`_conf_schema.json`、`policy.py`、`sessions.py`、`metadata.yaml`、`README.md`、当前 mission 的开放规格（OpenSpec）和状态记录、手动上传 ZIP。
- 不改 QQ 准入、工作目录、命令、代理权限和进程参数格式。用户继续在 AstrBot 自行上传并填写配置；不直接覆盖安装目录。

## 实施任务（Tasks）

- [x] 1. 更新配置键与 AstrBot 配置表单：移除共享 `default_model`，增加 `default_claude_model`、`default_codex_model`，两者默认为空字符串。
- [x] 2. 在 `policy.py` 按代理类型解析默认模型，保留群规则 `model` 优先级；在 `sessions.py` 对持久化会话代理与当前配置代理不一致的情况，取持久化代理的独立默认模型。
- [x] 3. 将 `metadata.yaml` 和 `constants.py` 版本同步提升至 `0.1.13`；更新插件 README，说明新字段、旧字段停用及已存在会话的行为。
- [x] 4. 更新 `spec/proposal.md`、`spec/design.md`、`spec/tasks.md` 和必要的 mission 记录，使本增量有对应验收点。
- [x] 5. 从插件源码目录生成根层含 `metadata.yaml` 的上传 ZIP；已核对配置 JSON、Python 语法、版本和 ZIP 根层。真实 QQ 与两种 CLI 回复仍需用户安装后验收。

## 验收标准（Acceptance Criteria）

- 配置表单能分别填写 Claude Code 与 Codex 默认模型；旧 `default_model` 不再出现在表单或参与解析。
- 群规则 `model` 非空时优先；否则按实际执行代理选择对应默认模型；空值时两种适配器都不发送 `--model`。
- 已有会话的代理类型与当前规则不同，不会收到另一代理的模型名。
- 版本均为 `0.1.13`，上传 ZIP 根层可被 AstrBot 识别；阶段 1 的真实双代理验收仍保留待办。

## 本轮不做 / 后续阶段（Deferred Scope）

- `/model` 聊天命令和自动模型发现：本轮只修静态默认模型字段；第一阶段双代理运行验收后进入阶段 2 完成，不代表放弃。
