## 目标与成功标准

将 `cc-ding` 的通用业务能力迁移到 AstrBot 插件，由 AstrBot 已有平台适配器（Platform Adapter）承担 QQ 等平台消息接入。插件提供统一配置、管理页面与生命周期，保留 Claude Code 和 Codex 的原生代理能力（Agent Capability）及 `cc-ding` 已有的通用业务能力。

成功标准：

1. 已配置的 QQ 群成员都能与代理对话；同群共享会话（Session），每群固定一个工作目录（Working Directory），私聊按用户独立会话与目录配置。
2. 文件权限与工具调用权限分别配置。所有用户的代理文件访问都限于对应工作目录；白名单用户最多可读写，非白名单用户只读。群级策略是权限上限，私聊独立配置，每次执行按实际发送者重新计算有效权限。
3. Claude Code、Codex 能在群聊和私聊完成多轮对话、恢复、任务处理与中断；代理自身根据本次可用工具元数据选择工具，不把所有意图和工具路由硬编码为关键词分支。
4. 通用功能经过逐项映射与验证，包括 Web Console 管理能力和代理间通信（A2A）；钉钉专属功能以 AstrBot 可提供的等价交互承接，不复制无意义的钉钉协议字段。
5. 只读用户无法通过直接文件工具、Shell、Skills、MCP、Hooks、定时任务、A2A 或管理入口读取目录外的用户文件或修改项目文件。权限越界测试必须失败关闭（fail closed）。
6. 插件源码按模块职责组织；平台适配、身份权限、会话任务、代理执行、管理页面和 A2A 通过明确接口连接，避免继续以钉钉入口类承载全部业务。

## 架构与职责

```text
QQ / 其他 AstrBot 平台
  → AstrBot 平台适配器（Platform Adapter）
  → AstrBot 插件：事件归一、身份映射、回复、配置、管理页面、进程生命周期
  → 本地进程通信（IPC）
  → 迁移后的 cc-ding 通用核心：权限决策、会话、任务、命令、调度、A2A
  → Claude Code / Codex 适配器（Agent Adapter）
  → 按请求隔离的代理执行环境（Isolated Runner）
```

- AstrBot 插件是用户安装和配置的入口；随插件管理的 Node 进程承载迁移后的 TypeScript 核心，不要求用户另行部署一个钉钉机器人。
- 核心接收平台无关的消息封套（Message Envelope），只使用群、用户、会话、消息段与回复目标等抽象字段，不依赖钉钉工号、Webhook 或 Token。
- 工作目录仅承载用户项目文件。会话记录、队列、凭据、配置和审计记录保存在插件专属数据区，不放在群工作目录内供普通成员读取。
- 本地进程通信（IPC）优先使用插件持有的标准输入／输出管道，避免额外监听端口；协议需要请求编号、超时、中断和重启恢复，不能让 QQ 消息直接访问进程控制接口。
- 隔离执行环境按每次请求的有效权限创建，而不是按共享会话固定权限。宿主系统和代理运行时所需资源由受控启动器提供，不能作为普通文件工具可浏览的目录暴露给代理。

## 权限模型

| 场景 | 文件权限上限 | 工具权限来源 | 会话 |
| --- | --- | --- | --- |
| 群内白名单用户 | 对应群目录内可读写 | 用户允许集与群允许集取交集 | 同群共享 |
| 群内非白名单用户 | 对应群目录内只读 | 用户允许集与群允许集取交集 | 同群共享 |
| 私聊 | 对应用户私聊目录，按独立配置与白名单确定只读或读写 | 用户允许集与私聊允许集取交集 | 每用户独立 |

- 群设置为只读时，白名单用户也只能读；群设置为可写时，非白名单用户仍只能读。
- 工具是否暴露给代理由本次有效允许集决定；代理在允许集内自主选择工具。任何获准工具也必须服从文件边界，尤其是 Shell、MCP、Hooks 与调用其他代理的能力。
- 群共享历史不等于共享执行权限。每条 QQ 消息进入核心时重新计算发送者身份、群策略及工具集；会话恢复不能沿用前一条消息的写权限。
- 定时任务记录创建者与目标会话，执行时重新验证其当前权限。A2A 请求必须有可验证来源与目标群授权，不能通过伪造 QQ 用户或默认服务身份取得写权限。管理页面的配置操作独立鉴权，触发代理执行时仍经过同一权限决策层。
- 禁止使用原 `cc-ding` 的 `bypassPermissions`、Codex 完全访问沙箱或提示词式问答模式（QA Mode）替代上述文件边界。

## 功能迁移范围

| 功能族 | 本轮处理方式 |
| --- | --- |
| 消息与会话 | 迁移群聊／私聊、多轮对话、会话持久化、`/new`、`/resume`、`/end`、日志、消息队列、去重、中断与继续；输入输出改为 AstrBot 消息接口。 |
| 代理执行 | 迁移 Claude Code、Codex 适配、模型选择、流式结果、超时看门狗（Watchdog）、重试与密钥管理；增加统一的每请求权限上下文。 |
| 任务与协作 | 迁移任务队列、定时任务、一次性提醒、待办、快捷菜单与代理间通信（A2A）；所有后台入口统一重验权限。 |
| 内容输入与输出 | 用 AstrBot 消息段承接文本、图片、文件、引用、提及和可用的进度反馈；具体平台能力缺失时给出明确降级反馈。 |
| 管理能力 | 把原 Web Console 的配置、会话、模型、密钥和状态管理映射到 AstrBot 插件页面（Plugin Page）及插件配置，不再维护钉钉 Client 管理语义。 |
| 管理命令 | 保留仍有意义的帮助、信息、授权、工作目录、模型、日志和任务管理能力；原钉钉专属 `/cfg` 字段、手机号／工号解析、Webhook、AI Card 与 PM2 重启入口改为 AstrBot 对应操作或明确取消对应命令。 |

“完整迁移”指通用能力及其可用的 AstrBot 等价交互，不指保留钉钉 API、Token、AI Card 数据格式或钉钉特有的身份模型。计划阶段需建立逐命令／逐配置项映射表，避免遗漏或把不等价行为悄悄当作已迁移。

## 错误处理与验证

- 代理命令缺失、认证失效、超时、进程崩溃、插件重载和 AstrBot 平台发送失败时，保留会话可恢复性并返回可理解的状态；不向群消息输出凭据或内部路径。
- 同群并发请求沿用显式队列与中断语义；权限在出队执行时再次计算，避免排队期间配置变化造成越权。
- 隔离可行性是实施前段的验证门禁：计划需安排可复现验证，覆盖目录外读取、符号链接、写入、Shell、MCP、Hooks、A2A 与定时任务入口。若当前运行方式不能满足边界，应回退设计，而非放宽权限。

### 2026-09-28 23:58:41 +08:00｜运行平台补充对齐

- 插件最终在 Windows 或 macOS 原生运行，不以 Ubuntu／WSL 为安装或运行前提。Python AstrBot 插件入口和为复用 TypeScript 核心而存在的 Node 进程均须支持这两个平台。
- 用户确认非白名单“只读”应优先使用 Claude Code、Codex 原生权限能力；文件权限与工具调用仍分开配置。是否开放 Shell、MCP、Hooks 等能力，以每个平台、每种代理的真实越权验证结果为准，未验证的组合默认禁用。
- Claude Code 在原生 Windows 上的内置 Shell 沙箱不可用；不能把 `plan` 模式等同于目录外读取隔离。macOS 可单独验证其内置沙箱。Codex 原生 Windows 与 macOS 的权限配置也必须分别验证。该补充修正原计划中的 WSL 优先假设，不改变前述目录边界与迁移范围。
- 迁移验收需覆盖通用核心单元测试、AstrBot 适配器测试、Claude Code／Codex 真实进程测试、QQ 群和私聊端到端测试、管理页面及 A2A 授权测试。
- 本地参考实现 `cc-ding/` 采用 MIT 许可；迁移源代码时保留必要的版权及许可声明，并确保最终插件源码是仓库内可追踪文件，而非依赖被忽略的本地克隆目录。
