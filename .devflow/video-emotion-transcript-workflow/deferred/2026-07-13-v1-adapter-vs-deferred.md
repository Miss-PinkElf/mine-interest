## 本轮已做第一版（不是延期）

这些能力在 `spec/tasks.md` 已勾选完成，代码与测试存在，但实现为**可替换适配层 / 本地桩**，用于打通审核闭环：

| 对象 | 第一版做到什么 | 暂不做的“加深部分” | 后续触发条件 |
| --- | --- | --- | --- |
| FFmpeg 媒体信息 / 质量报告 | `MediaService` 可注入探测 + 质量维度字段 | 真实 FFmpeg 深度分析与阈值标定 | 样本验证需要可靠 BGM/噪声/响度指标 |
| 条件预处理与三音轨 | 路由规则 + `audio_raw/light/stt_ready` 产物策略 | 真实人声分离/去混响/降噪命令 | 强 BGM 样本上 STT 基线不可用时 |
| STT / VAD / 说话人分离 | `TranscriptionEngine` 协议 + 显式 Fake STT 演示任务，可上传后自动生成待审核片段 | SenseVoice / WhisperX / pyannote 真推理 | 需要真实时间轴转写效果时 |
| 片段音频播放 | 审核页保留播放器控件和片段时间范围 | 当前未接入上传媒体的音频源，播放器显示 `0:00`；真实片段回放与音频路由 | 进入真实媒体处理与 STT（语音转文字）阶段，确定片段媒体访问与验收样本时 |
| 视觉/音频专用证据 | Orchestrator 标准化输出 + Evidence 映射 | MediaPipe 等 GPU 模型 | benchmark 要求客观视觉事实时 |
| 审核证据面板 | 三栏工作台与证据展示组件已存在 | 演示任务无真实情绪/表情证据，面板显示空状态；真实证据生成及引用 | 真实音视频证据链路与可信样本验收标准确定后 |
| 云端 LLM 融合 | Provider 协议 + 设置 API + 本地回退融合 | 真实 HTTP 调用与多模态帧上传策略 | 已配置本机 Provider 且需语义解释时 |
| Markdown/JSON 导出 | 后端生成文件并在页面显示本机产物路径 | 浏览器直接下载文件 | 本机路径交付不满足用户使用方式，或进入跨设备/打包分发阶段时 |
| Playwright E2E | 规格文件已落盘 | 本机浏览器安装与全链路自动跑 | 前后端常驻联调并要回归门禁时 |
| Windows + CUDA 3080 | 文档约束为目标环境 | 本机/目标机真实显存与模型加载验证 | 移植到目标 Windows 环境时 |

## 明确延期（本轮未实现，不是永久放弃）

继承并重申 `2026-07-10-mvp-deferred-scope.md`：

| 延期对象 | 本轮暂不做原因 | 后续触发条件 |
| --- | --- | --- |
| Electron / 登录 / 多用户 / 云端部署 | 个人本地闭环优先 | 需要分发安装包或协作时 |
| 复杂波形/多轨剪辑 | 偏离审核 MVP | 切分合并文本审核不够用时 |
| 平台下载 / 自动评论 / 网页搜索 / 反向搜图 | 合规与成本未验证 | 审核链路稳定后以手动导入先导 |
| 全量动作识别 / 全自动梗理解 | 误判风险高 | 有可测试的特定领域集合时 |
| n8n / 通知 / 第三方分发 | 核心 API 刚成型 | 出现稳定集成需求时 |
| 模型微调 / 跨视频分析 | 缺标注与指标 | 预训练基线不达标且有数据时 |

## 使用说明

- 新会话**不要**把「适配层」当成未完成 tasks 重新从零实现。
- 新会话**不要**把延期项提前做进 V1。
- 新会话先由用户手动验证本轮演示闭环，再对齐真实能力的优先顺序；选一个适配层换成真实实现，并用真实样本验证。

## 2026-07-13 15:05:44 +08:00 补充：自动管线不算延期

- **JobRunner（上传后自动跑最小管线）** 属于 **第一版应加深的缺口**，不是 `deferred` 永久延期项。
- 延期项仍是 Electron/n8n/下载搜索/训练等；不要与 JobRunner 混淆。

## 2026-09-27 01:09:39 +08:00 补充：演示闭环与真实能力边界

- 显式演示模式（Demo Mode）的 JobRunner（任务运行器）已完成第一版：上传后可自动产生 Fake STT 片段，进入审核、人工修订、确认与导出。自动管线不再是待办缺口。
- 真实语音转文字（STT）、真实 FFmpeg 处理、音视频情绪证据和真实云端大语言模型（LLM）调用仍属于后续加深；本轮先验证状态和人审交互，缺少可信真实样本与模型验收，因此暂不接入。用户手动验收演示闭环后，再按真实样本需求进入下一阶段对齐。
- 大语言模型（LLM）基于工具元数据自主选择分析工具只是候选方向（Candidate）；当前任务状态、持久化和失败判定保持确定性。待真实证据链路可用且讨论可控边界后，再决定是否进入计划（Plan）。
- 应用内后台任务只覆盖单机单进程；真实推理耗时、重启恢复或并发负载暴露不足时，再评估持久队列与自动重试入口。本轮未实现，不代表永久放弃。

## 2026-09-28 11:35:53 +08:00 补充：用户验收后的能力边界

- 用户在 Mac mini 上完成演示任务的人工修订、确认与导出验收；确认与导出状态同步问题已修复。**此验收只覆盖演示审核闭环**，不构成真实媒体识别、播放器或情绪理解的验收。
- 真 STT（语音转文字）、真实媒体预处理、片段回放、音视频情绪证据和真实云端 LLM（大语言模型）调用是第一版适配层后续加深对象；本轮继续暂缓，是为了先固定上传、审核和导出交互。用户选择真实能力阶段并准备代表性音频/视频样本与验收标准时，重新对齐并计划，不视为永久放弃。
- 浏览器文件下载仍以本机产物路径交付为第一版边界；当用户需要直接下载、跨设备访问或打包分发时进入独立体验改进阶段。
- TTS（文字转语音）在本轮仅用于澄清概念，未作为产品需求提出或批准；若用户希望生成语音，再单独对齐用途与范围。
- 大语言模型（LLM）辅助意图识别和基于工具元数据自主选工具仍为候选项（Candidate）；只有真实证据链路可用、可控性和可复现验收确定后才讨论是否进入计划（Plan）。
