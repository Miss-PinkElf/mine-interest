## 1. 目标

目标不是为普通 STT（Speech to Text，语音转文字）追加孤立的情绪标签，而是建立面向个人本地使用的“证据驱动视频理解工作台（Evidence-driven Video Understanding Workbench）”。

用户输入一段本地视频或音频后，系统按时间轴生成可编辑片段。每个片段关联原始文本、说话人、音频情绪和事件、画面/人脸/姿态证据、云端 LLM（Large Language Model，大语言模型）解释、置信度和人工修订，最终输出 Markdown 与 JSON。

## 2. MVP 范围

### 本轮包含

- React + Vite 浏览器工作台和 Python FastAPI 本地服务，仅供个人本地使用。
- 本地视频/音频文件输入、任务进度和阶段日志摘要。
- 本地媒体预处理、STT、说话人分离、初始时间分段与关键帧抽取。
- 本地专用模型（Specialized Model）提供人脸、基础表情、姿态、音频情绪和音频事件等结构化证据。
- 云端多模态 LLM（Multimodal LLM）结合文本、关键帧和专用模型证据，生成有依据的语气、情绪与语境解释。
- 片段审核：回放、视频/关键帧预览、文本和结论编辑、切分、合并、删除、确认。
- 受影响片段的局部重分析，以及 JSON / Markdown 导出。

### 本轮不做 / 后续阶段

- Electron、登录、多用户、云端部署。
- 复杂波形/频谱编辑、多轨剪辑和复杂批量编辑。
- 平台自动下载、自动评论抓取、未确认合规性的爬取。
- 自动反向搜图、自动网页搜索、全量通用动作识别、自动梗库、全自动梗理解。
- n8n workflow、外部通知、第三方系统分发、模型微调、自训练情绪模型和跨视频分析。

延期原因：第一版先验证单视频的可编辑证据链和人工审核闭环。延期项依赖合规边界、额外成本、样本验证或产品化稳定性，不是永久放弃；当基础链路完成真实样本验证后再进入后续阶段。

## 3. 架构与职责

```text
React 本地工作台
  -> FastAPI 本地服务
     -> 本地媒体工具与专用音频/视觉模型
     -> 本地任务、产物与审核记录
     -> 云端 LLM / 多模态模型适配层（Provider Adapter）
  -> JSON / Markdown

后续：FastAPI 能力可由 n8n 作为工作流壳层调用。
```

- 本地工具层（Tool Layer）：执行可复现的音视频处理、模型推理和产物管理。
- 工具注册表（Tool Registry）：维护工具输入、输出、前置条件、成本和运行位置等元数据。Agent（智能代理）读取元数据后选择工具，不能把工具顺序硬编码在 Prompt（提示词）中。
- Agent 编排层（Agent Orchestration）：仅作条件路由，例如质量差时启用预处理、多人时启用说话人分离、视觉证据不足时请求云端分析、证据冲突时标记人工审核。
- 云端 LLM：解释和整合证据，不替代 STT、人脸检测、姿态估计或其他专用模型。
- React 前端：个人审核与导出工作台，不承载媒体模型推理。

云端模型通过 LLM Provider Adapter 调用；`base_url`、模型名和密钥为本地配置。上层业务逻辑不得绑定 OpenAI、Gemini 或任一兼容服务。原始媒体默认不离开本机；仅发送当前片段必须的文本、经过筛选的关键帧和证据摘要。

## 4. 预处理与双音轨

参考 `数据集处理.md` 的人声分离、去混响、谨慎降噪和切片经验，但不直接照搬训练数据清洗流程。情绪和语气判断需要保留气声、停顿、能量和尾音，过度处理会损害关键证据。

```text
原始媒体
  -> FFmpeg 抽取音频与质量报告
  -> 条件路由：人声分离 / 去混响 / 保守降噪 / 响度标准化
  -> audio_raw / audio_light：情绪判断和人工试听
  -> audio_stt_ready：STT 与说话人分离
  -> VAD 初始分段
  -> STT、说话人分离修正时间片段
```

- 质量报告至少包含 BGM、噪声、混响、语音占比、响度、削波和多人重叠的检测或估计结论。
- 原音清晰时跳过人声分离和强降噪；BGM 明显时才使用 audio-separator / BS-Roformer 等工具。
- 去混响和降噪按质量结论选择性启用；响度采用可配置的 Loudness Profile（响度配置），不写死训练材料的单一阈值。
- 保留每步输入、输出与处理记录，前端可回听原始或处理后片段。

## 5. 专用模型与 LLM 协同

采用“专用模型优先的多模态证据融合（Specialized-Model-Prioritized Multimodal Evidence Fusion）”：

1. 专用模型优先提供客观事实：人脸存在与位置、面部关键点/混合形状（Blendshapes）、头部方向、姿态关键点、基础表情候选、声学特征和音频事件。
2. 云端 LLM 负责语义解释：反讽、调侃、尴尬、画面与话语之间的矛盾、可能的梗和内涵。
3. LLM 输出必须列出所用证据和不确定性，不能无理由推翻高置信度专用模型事实。
4. 专用模型、音频与文本语义冲突时，结果进入人工审核，不自动掩盖冲突。
5. 后续以人工确认样本校准各类证据在实际内容中的可靠性，不预先硬编码固定权重。

关键帧初始策略可按约五秒采样，但必须按片段时间边界补充开始、中间和结束附近的帧，避免视觉表情错配到相邻语句。

## 6. 数据与审核

一个项目任务（Project Job）对应一个本地媒体文件和独立的本地产物目录：

```text
ProjectJob
  -> SourceMedia
  -> MediaPreparation
  -> Segments[]
  -> Evidence[]
  -> ReviewState
  -> ExportArtifact
```

每个时间片段（Segment）至少保存：`start`、`end`、说话人、`raw_text`、`edited_text`、`final_text`、原媒体时间范围引用或片段音频、音频情绪/事件、视觉观察、叙事解释、置信度、不确定性、证据标识、审核状态、操作记录和“需要重新分析”标记。

- 模型原始结果永不覆盖；人工修改写入独立字段。
- 切分、合并、删除均形成审核操作记录。
- 时间边界、文本或说话人变化后，只标记并重跑受影响片段。
- 导出使用已确认的最终结果，可选附带原始结果与审核记录。

## 7. 前端模块

- 任务页：选择本地媒体、提交任务、查看阶段状态与失败摘要。
- 片段审核页：片段列表、原始音频回放、视频/关键帧预览、文本与结论编辑、切分/合并/删除/确认。
- 证据面板：音频、面部/姿态、OCR、LLM 解释和置信度，明确区分客观模型事实与语义推断。
- 导出页：导出 JSON / Markdown。
- 设置页：本地模型开关与云端 Provider 配置；密钥只保存在本机。

## 8. 恢复、隐私与验收

- 工具或云端调用失败时保留已完成产物，并记录错误摘要和重试入口；云端失败只重试当前片段。
- 没有人脸、姿态或语音是正常结果，不视为任务失败。
- 同时只运行一个重 GPU 阶段；模型按阶段加载和释放。
- 原始模型结果、处理结果、人工修改和最终导出保持版本可追溯。
- 原始视频、音频、切分音频、完整关键帧和审核记录默认只留在本机。每次云端调用记录已发送的证据。

验收用真实本地样本覆盖单人、多人、BGM、噪声/混响、清晰人脸、遮挡人脸和无人脸情况。必须能够生成、播放、编辑、切分、合并片段；展示原始文本、专用模型证据、云端解释和不确定性；确认后导出；修改单片段只触发局部重分析；并在云端或单个专用模型失败时保留已有结果和可恢复操作。
