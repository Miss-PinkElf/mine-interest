## 自动动作

| 故障 | 自动动作 | 证据位置 |
| --- | --- | --- |
| 测试实例残留 | 启动 suite 前检查端口与 PID；确认属于测试实例后停止 | `report.md` 操作记录：`已停止残留测试实例` |
| 测试实例启动失败 | 最多重试 2 次；每次失败后停止残留实例再重试 | 操作记录：`测试实例启动失败（第 N 次）` |
| 热重载失败 | 停止测试实例并按启动重试流程重启 | 操作记录：`热重载失败，改为重启测试实例` |
| 插件副本过期 | 每次执行前按 `plugin_sources` 解析插件源并重新同步到测试实例 | `data/plugins/<plugin>` |
| 历史消息造成假通过 | 按 `since_time` 过滤，并加 `timeouts.log_window_padding_seconds` 窗口 | 各用例 `messages.json` |
| 测试端口被占 | 区分自有实例与未知进程；未知进程只报告并停止 | `doctor` / 启动阶段输出 |
| 单个用例失败 | 记录证据后继续执行剩余用例（插件类失败） | `report.md` 失败摘要 |

## 需用户确认

1. 暂停、恢复生产 AstrBot。
2. 修改生产配置（包括临时启用或禁用 OneBot 客户端；脚本会自动生成 `.bak-<时间戳>` 备份）。
3. 删除任何数据、日志或报告。
4. 关闭脱敏（`--no-redact`）。
5. 在测试端口被未知进程占用时，是否由用户自行终止该进程。

## 禁止

- 杀未知进程。
- 修改被测插件源码。
- 自动扫码登录。
- 在生产实例上直接执行测试用例。
- 静默跳过失败或不可测项。

## 自愈上限

- 同一故障最多自动修复 2 次。
- 超过上限后停止执行，输出已尝试动作、证据路径与建议，由用户决定下一步。
- 环境类失败（配置错误、账号不匹配、端口被未知进程占用、插件源缺失）立即停止。
- 插件类失败（断言不通过、插件无响应）记录证据后继续执行剩余用例。

## 边界

- 自愈只作用于测试侧资源；生产侧一律需要用户确认。
- 报告中的「操作记录（Ops）」是自愈过程的唯一可信证据，排查时优先查看。
