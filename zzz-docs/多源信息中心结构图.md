## 01 全景：先收住，再编译

![多源信息中心全景](images/source-hub/01-overview.png)

四类输入进收集层，原文带结构化元数据（Structured Metadata）后只进不出。人在回路（Human-in-the-loop）做去留，大语言模型维基（LLM Wiki）负责编译。Obsidian、命令行接口（CLI, Command Line Interface）、应用程序接口（API, Application Programming Interface）只是皮肤。

```mermaid
flowchart TB
    chat["聊天平台 Chat<br/>QQ / 微信 / TG / Discord"]
    docs["文档仓库 Docs<br/>GitHub / 语雀 / Obsidian"]
    public["公开内容 Public<br/>B站 / 小红书 / X / 微博"]
    self["自己手记 Self<br/>想法 / 冷门知识 / 项目"]

    collect["收集层 Collect<br/>原始资料 Raw Sources · 只进不出"]
    human["人在回路 Human-in-the-loop<br/>粗收 → LLM 建议 → 人做去留"]
    wiki["编译层 Compile<br/>LLM Wiki · 摘要 / 实体 / 主题 / 综合"]
    skin["展示层 Present<br/>Obsidian / CLI / API / 插件源"]

    chat --> collect
    docs --> collect
    public --> collect
    self --> collect
    collect --> human
    human --> wiki
    wiki --> skin
```

## 02 三层：收集、编译、展示不要混

![三层分工](images/source-hub/02-three-layers.png)

Karpathy 的方法默认资料已经在文件夹里。当前想法真正多出来的难点，是左边那一层：怎么把 QQ / 微信 / GitHub / 小红书这些活水源持续接进来。

| 层 | 英文 | 做什么 | 本轮判断 |
|---|---|---|---|
| 收集层 | Collect | 捞进来、留原文、带 metadata | 当前想法独有，也更难 |
| 编译层 | Compile | 按 Schema 编成 Wiki 页 | 直接借鉴 LLM Wiki / Graphify |
| 展示层 | Present | 给人逛，给 AI 管 | 只是皮肤，可以后换 |

```mermaid
flowchart LR
    collect["收集层 Collect<br/>活水源 + 原文 + metadata"]
    compile["编译层 Compile<br/>Schema + Wiki 页"]
    present["展示层 Present<br/>Obsidian / CLI / API"]

    collect --> compile --> present
```

## 03 编译回路：原文不动，Wiki 会长

![编译回路](images/source-hub/03-compile-loop.png)

三层文件约定：

- 原始资料（Raw Sources）：不可改，真相源（source of truth）
- Wiki 页面：LLM 拥有，人只读
- 结构约定（Schema）：告诉 LLM 怎么整理、怎么更新

三个日常动作：摄入（Ingest）、查询（Query）、巡检（Lint）。两份特殊文件：`index.md` 是目录，`log.md` 是只追加的时间线。

```mermaid
flowchart TB
    raw["原始资料 Raw Sources<br/>不可改 · LLM 只读不写"]
    wiki["Wiki 页面<br/>LLM 维护 · 人只读"]
    schema["结构约定 Schema<br/>例如 AGENTS.md"]

    ingest["摄入 Ingest"]
    query["查询 Query"]
    lint["巡检 Lint"]

    raw --> wiki
    schema --> wiki
    ingest --> wiki
    query --> wiki
    lint --> wiki
    query -.->|"好答案回写"| wiki
```

## 04 组织时机：不要先赌向量库

![组织时机对比](images/source-hub/04-timing.png)

换的是处理时机，不是再换一个检索算法。

| 路线 | 组织时机 | 知识形态 | 本轮位置 |
|---|---|---|---|
| 传统 RAG | 提问时 | 文本碎片（chunk） | 不先做 |
| LLM Wiki | 资料进入时 | 摘要 / 实体 / 综合页 | 主航道 |
| 知识图谱（Knowledge Graph） | 进入或定期构图 | 节点和边 | 页面互相指认后再补 |
| 目录 + 关键词 | 写入时建目录 | 文件、标题、标签 | 最小可运行导航层 |

难度顺序已经排过：

1. 先能存
2. 再能编
3. 再能连
4. 最后检索

```mermaid
flowchart LR
    store["1 先能存<br/>原文 + metadata"]
    compile["2 再能编<br/>Schema + Wiki"]
    link["3 再能连<br/>交叉引用 / 图谱"]
    search["4 最后检索<br/>目录 → 关键词 → 向量"]

    store --> compile --> link --> search
```

## 05 活水源：系统给候选，人做去留

![活水源筛选](images/source-hub/05-live-source-filter.png)

论文、书籍、会议纪要默认是已经人选过的资料。QQ、微信、B 站评论、小红书帖子默认是高噪声流。所以收集层必须多一跳：值不值得留下。

```mermaid
flowchart LR
    rough["粗收<br/>原文和来源不丢"]
    suggest["LLM 建议<br/>去留 / 标签 / 主题"]
    human["人做去留<br/>判断权不下放"]
    compile["编译<br/>摘要 / 标签 / 主题页"]

    rough --> suggest --> human --> compile
```

不想断舍离，所以系统必须容纳「现在不一定有用、以后可能有用」；但不能因此放弃筛选。

## 和原稿手绘图的对应

原稿中间是一个圆：个人知识库 + 多种信息源 + 笔记软件。四周是输入，下面是沉淀。

结构图没有改这个判断，只是把「中间那个圆」拆成了两层：

- 收集层负责「不要让来时路断掉」
- 编译层负责「让留下来的东西开始复利」

笔记软件、Obsidian、自研界面，都还只是后面那层皮肤。
